# 短线题材统一为 Vibe 事件标签

2026-11-02。用户确认三页签布局，并要求所有短线周期、单日题材证据及事件树统一使用 Vibe-Astock 的事件题材。

## 身份与数据口径

- 使用 `shortline_themes.py` 的 `clean_reason` / `tags_of`：涨停原因按 `+` 拆分，最多四个标签、四十字，不截断后续半个标签；过滤纯属性词及“国资／国企／板块”后缀。
- 事件标签逐字保留；不按 DC 行业或概念映射，不再合成“零售主线”等旧家族。事件代码为名称的稳定摘要，名称仍为来源原文。
- `vibe-event-themes-v1` 表示题材身份；`theme-cycle-event-v3` 表示跨日周期实现。核心认证、固定前后排、阶段确认及退出规则保留。
- 周期观察成员仅为截至复盘日曾有同日原因支持的涨停股，不冒充全行业或全概念成分。新事件在此前完整可观察日期属于已知零；缺原因属于未知。
- 缺原因股票在事件归属上未知，即使不在已有观察成员内也进入待核验队列。不能据此确认扩散归零或触发退出。

## 已切换的使用位置

1. `theme_daily_job` 默认从完整历史行情输入按日期前缀重建事件题材，不再请求 `dc_index` / `dc_member`。显式旧 reader 仅为离线研究兼容，发布构建仍转换到事件口径。
2. 周期归档、归因明细共同使用同一修订号和同一事件口径，通过既有 Mongo 指针原子发布；原修订保留。旧 DC 修订读取时明确显示待迁移，不冒充新口径名单。
3. 新的输入文件写入 `inputs/日期/vibe-event-themes-v1`，不覆盖原 DC 输入基线。
4. 收盘复盘的旧 `theme_evidence` 返回事件视图位置标记，不再计算旧 DC 题材；历史原始快照保留。昨日涨停反馈中的题材改为该日原因标签，行业字段仍明确为行业。
5. 决策研究的“短线情绪”来源改为同日事件样本；真实板块研究和 AI 硬件板块继续使用其独立板块分类，标注成员范围，禁止用旧复盘 DC 标签冒充短线来源。

## 历史修复

`extend_market` 保持旧行情、核心与固定队列；历史原因按同日有效新记录修复，保留旧有效且新记录缺失的股票。错误日期和空响应不覆盖完整缓存，修复来源及保留代码有元数据。

`python -m shilun.jobs.migrate_event_themes --date YYYY-MM-DD` 使用已验收且结束日相同的完整缓存，补读数据库中同日原因后连续回放；不发起行情或原因下载。迁移不只计算最后一天，避免丢失原有历史阶段。
