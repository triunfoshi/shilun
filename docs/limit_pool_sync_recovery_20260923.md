# 2026-09-23 涨停池同步连接超时修复

## 现象与核对

- 本地后台日志连续两次记录 `POST /api/v1/data/sync-limit-pool` 的 `ServerSelectionTimeoutError` / HTTP 503。
- 异常发生在同步函数的数据库构造阶段，尚未进入涨停池抓取和写入。该构造原先位于局部异常处理之外，最终只返回全局的“请核对记录是否已保存”。
- 数据状态接口也曾返回 `mongo_connected=false`，本机 ECS 隧道日志存在连接超时、断开及重新连接记录；不能仅凭无时间戳的隧道日志判断某次断开的具体起因。
- 后续只读核对：ECS MongoDB active，内存可用约 4.3 GB，磁盘使用率 41%，没有发现数据库服务停止或资源耗尽。
- 恢复连接后、补跑前：9月22日63条且无重复；9月23日0条，没有成功同步标记。历史数据没有被本次失败清空。

## 修复

1. 涨停池同步和数据状态读取不再在每次请求时初始化全应用一百多项索引。连接选择预算为15秒，读写预算为30秒。
2. 同步前 ping 检查；构造和连接失败明确提示本次未开始抓取或写入。同步阶段的数据库错误、数据源错误分别返回503、502，不将缺数标记为零。
3. 涨停池任务仅准备自身两项索引，新增 `(ticker, trade_date)` 唯一索引；同步仍按该键 upsert。重复同步同一天更新原记录，状态写入失败不删除已写入的数据。
4. 数据状态读取连接失败返回“暂时无法核对”，避免误报成实际缺数。

## 验证

- 45项测试通过，覆盖连接前失败、写入中断、状态写入失败、来源失败、真实空池与状态读取失败。
- 修复后的同步函数成功补入9月23日51条；数据库核对为51条、51个不同股票代码、同步状态success。
- 本地后台重载后，经实际HTTP接口再次同步9月23日成功返回51条。
- 数据状态接口返回 `mongo_connected=true`，涨停池 `ok=true`，显示“2026-09-23 涨停51只”。9月22日63条保留。
- 同期板块预计算任务已完成，未因本次修复被中断。
- 此修复已在Mac本地后台生效；未在本次任务重新部署ECS采集程序。新增数据库唯一索引已生效。

网络断开期间仍无法访问云端库；本次改动减少不必要的往返，并准确区分失败阶段，不把数据库不可达伪装成同步成功。
