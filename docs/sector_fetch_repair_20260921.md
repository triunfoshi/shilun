# PART2 查询与强制重算请求修复（2026-09-21）

## 现场与原因

用户当前 Chrome 页面保留了「请求失败：Failed to fetch」。该错误表示浏览器没有拿到可用 HTTP 响应，不能直接判定为板块计算失败。本轮检查时本地 8000 服务在线、同源地址正常；重新操作没有复现连接错误，无法仅凭旧提示唯一确定之前断线的诱因。

实际重新查询发现：9 月 18 日缓存可读取，但 9 月 21 日尚无板块缓存，接口返回 HTTP 400 和 `detail: 板块动向数据未预计算…`。前端只检查 `error.message`，漏读 `error.detail`，所以预计算引导没有出现。界面还把状态读取错误标为「计算失败／已停止」，保留不准确的 90—240 秒及两分钟倒计时。

## 修复

- 正确识别 FastAPI `detail`；缓存缺失显示「该日期尚无板块归档」及生成按钮。
- 板块查询和进度查询遇到网络连接错误最多重试两次。POST 提交不自动重放，避免无法确认响应时重复提交。
- 连接中断、进度读取失败、提交状态不明确分别显示可恢复提示；不把连接失败当作后台任务已停止。
- 请求超时覆盖响应正文读取；成功、HTTP 错误及网络异常都释放计时器。
- 任务提交／状态接口的 Mongo 操作限时 20 秒，异常返回可读 503，避免浏览器先超时；原有同日任务去重继续保留。
- 去掉强制计算的 90—240 秒文案、假百分比和两分钟倒计时，显示后台运行及实际已等待时间。
- 静态脚本版本升级至 `20260921-sector-fetch-v3`。
