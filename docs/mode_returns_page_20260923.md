## 页面分工

交易决策目录按「模式收益 → 明日预案 → 今日跟踪」排列。

- 模式收益：按盘后日期独立生成评估，展示环境、各组近期反馈、参与条件、中位数事件收益、红K频率、逐日换手量能和历史核心名单。
- 明日预案：引用同日固定版本评估，只展示结论和参与条件；保留指数量能、方向与核心、主备候选、次日流程图。历史统计筛选移到模式收益。
- 今日跟踪：沿用原逻辑，本轮没有接入新行情或执行策略。

成交额档、入组时间、T+N窗口只改变研究统计展示，不重写评估结论或预案路径。三组入组阶段不同，仍不按跨组收益选冠军。模式评估规则本轮保持不变；尚未新增同模式历史基准的改善/恶化评级或可参与性自动评分。

## 独立生产和引用规则

`mode_research.build_mode_research` 独立计算分组统计与评估，不执行方向筛选或MA5扫描。`engine.build_plan` 接收评估快照，校验日期、版本、输入数据指纹和内容摘要后引用，预案不再内嵌完整历史分组、事件和核心历史。

存储位置：

- `runtime/trade_decision/<日期>/mode-research/<内容摘要>.json`：不可变评估快照。
- `runtime/trade_decision/<日期>/mode-research.json`：该日最新评估。
- `runtime/trade_decision/<日期>/plan.json`：冻结预案，记录 `mode_research_ref`。

完全相同的输入复用原快照和生成时间。不同输入生成新快照；已有预案不因研究更新而改变。预案中的证据链接携带日期和精确快照编号；缺少该版本时显示缺失，不回退到最新评估或其他日期。模式收益页可用“读取最新评估”切换本日最新结果。

生成预案时若没有与当前输入匹配的评估，先生成并保存评估，再生成预案。读取操作不触发生成。新预案版本为 `decision-pilot-v3`，旧版预案保存在 `revisions` 中。

API：

- `GET /api/v1/trade-decision/mode-research/dates`
- `GET /api/v1/trade-decision/mode-research?date=YYYY-MM-DD`
- `GET /api/v1/trade-decision/mode-research?date=YYYY-MM-DD&snapshot_id=<内容摘要>`
- `POST /api/v1/trade-decision/mode-research/build?date=YYYY-MM-DD`

新旧生成任务共享单任务队列，避免并行计算；研究生成不会改写预案。数据源只读，生成结果写入本机研究目录。
