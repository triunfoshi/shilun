# P0 板块研究与全市场 MA5 迁移

2026-11-04。执行语言仍为 Python，页面、API 与数据库协议沿用现有系统。

## 执行链路

页面提交 → 云端 Mongo 持久任务 → ECS 单个重任务执行 → 同日依赖准备 → 日线初排 → 候选分钟补数 → 严格资格重排 → 同代板块与 MA5 结果发布 → 页面只读缓存。

- 两个页面共用任务客户端；网络中断只恢复查询，不自动重复提交。
- 相同日期、基准、参数的运行任务合并；完成结果只有输入修订及当前发布代次都匹配时才复用。
- 自动失败按5/15/30/60分钟退避，最多5次；耗尽后由明确的“重新发起计算”开启新任务。排队时间不算任务失联。
- 重任务与日线流水线共用 `daily_data_pipeline` 租约：3分钟期限、30秒心跳。P0在发布前重新核验归属，失锁保留旧归档；旧进程不会删除新所有者的锁。
- 任务内复用原始事实及相同口径日线特征，分钟确认和排名仍重算。
- 独立 MA5 全市场扫描快照按实际输入内容签名验证；完整 audits 分块存储，不删减样本，不与板块预选绑定。缓存不可用时重新计算。
- 日线和分类修订在计算期间变化时拒绝发布。轻量修订来自当日依赖回执、分类版本、同步水位和分钟元数据；绕过这些正式写入链路的手工历史修改需要显式刷新，MA5快照本身仍通过实际内容签名校验。
- 当日全市场价格覆盖不足80%、不足24交易日或缺同日基准时不覆盖旧结果；个别缺口继续按原资格门排除，资金与基本面缺口不填零。

## 代码收口

- `market/sector_service.py` 承担应用服务，后台任务不再反向导入 API。API减少453行，主要为搬出计算与缓存编排。
- `jobs/sector_precompute_job.py` 仅入队与消费，不再由 Mac Popen 启动计算。旧同步 HTTP 入口改为兼容入队，指数强制刷新也不能绕过队列重算板块。
- 研究 CLI `ma5_selection_job --apply` 改为入队；无 apply 的研究导出继续独立运行。
- `market/ma5_snapshot_store.py` 保存完整扫描，不持久化 DataFrame 或分钟评分。
- 可靠执行和测试代码增加，总代码行数不作为优化验收指标。

## 资源与部署

ECS按一次一个重任务执行；容器限制2 CPU、3 GiB内存，BLAS/OpenMP各1线程。源码只读挂载，重建容器不会丢失已发布源码；现有runtime/logs卷保留。

原始和新版本固定同一份2026-11-03事实、分类与分钟数据对照：初排和严格最终结果逐字段一致，7只MA5候选及8个板块排名一致。旧基线220.84秒含首次数据库读取和冻结文件写入，新版155秒使用冻结输入，不能据此直接宣称30%计算加速。新版测试峰值约2.1 GiB，实际生产任务另作验收。

离线验证：216项Python测试、64个子测试，3个Node脚本与JS语法检查通过。覆盖队列恢复、有限重试、同输入复用、参数隔离、缓存完整性、真实分钟补齐、严格MA5窗口和失锁拒发。

## 发布与回退

云端只发布9个P0模块及Compose资源配置，其余既有模块保留原版本。发布前宿主与现行容器的136个依赖源码逐文件核对一致；发布清单、备份和实际验收回执记录在 `research/evidence/p0_compute_migration_20261104/` 及 ECS发布目录。

本轮没有改动交易筛选规则，也没有引入C++。旧流水线内部其他消费者的发布时机保持原边界；其外层归属检查不等于所有内部写入均已实现数据库级fencing，本轮P0发布路径单独核验归属。
