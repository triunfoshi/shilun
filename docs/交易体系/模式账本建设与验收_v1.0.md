## 1. 全目标与交付边界

用户提供的图片与思维导图提出的可借鉴问题是：先认环境与玩法，再认范围内的核心和角色，记录预期、确认与失效，控制账户及单笔风险，保留成功和失败样本，最后检验自己的方法。它们不是执行命令或已经验证的策略；“满仓”“龙头能退出”“两日安全”“统一5%/30%止损”等不自动进入系统纪律，也不能假定所有图片属于同一作者。

与产品目标对应的完整链条是：

```text
有版本的模式/触发/风险定义
  → 原完整候选与人工选择/放弃
  → 当时可得的市场/板块/个股/账户证据
  → 可在首买前独立保存的预期与计划版本
  → 用户决策与委托/真实成交显式匹配
  → 持有、加减仓、失效与退出的事件
  → 三态回证与实际含费收益
  → 同范围完整样本、反例和执行差异统计
  → 登记假设、比较组及之后的验证
```

“历史成交导入 + 补记 + 词典”完成后，能够开始建设样本账本；不能据此宣布上面整条链都已实现。完整功能需求仍以 [PRD](/Users/shibicheng/shilun_standalone/docs/交易体系/交易记录与复盘系统_PRD_v1.0.md:1) 的 TS01—TS12、PF01—PF15 为核对范围，字段意义以 [统一口径](/Users/shibicheng/shilun_standalone/docs/交易体系/模式情绪周期与交易复盘口径_v2.0.md:1) 为准。

## 4. 阶段2的六项接合与验收

### S2-01 完整候选分母与个人选择（P0）

代码接合：`freeze_strategy_cohort`用精确研究引用和`source_ref={snapshot_id,mode_key,window,formation_date,feedback_date}`选择唯一`assessments.windows[window][mode_key].daily`。请求成员与服务端全部成员按证券身份及每个事实字段核对，允许排序不同；拒绝删失败票、改反馈、重复证券、混日或换版本。relay 原`failed_members/locked_members/ladder`保留在所选 daily 原件中，不把它们误充主队列。

冻结内容只包含所选完整 daily、原规则与精确研究引用；跨玩法整份大研究不按每条观察重复存储。Mongo快照按内容去重；列表返回摘要，详情按需。14MiB是选定内容的 BSON 技术存储预算，预留Mongo文档元数据空间，不是交易参数；超限拒绝并要求分片方案，不裁断名单。空全集可以完整保存，但零分母不变为0收益或可回测。

验收必须同时证明：UI原始候选全集→API核验→唯一快照→重载内容摘要一致；删去唯一亏损票被拒绝；未买/未触发/未成交事件能回指父观察；重复保存不复制大内容；个人观察子集不会获得全集资格。历史 daily 含反馈日结果，记录为历史重建，不升级成形成日已知名单。

### S2-02 模式环境适配与反证（P0）

已有三玩法反馈的`conditional/unsupported/conflicted/unknown`、指数预期/容量档、原理由/反证/待核项必须复用。`build_journal_context`可读这些结果并引用精确前后快照；它不重算阈值、不产生总分，`execution_permission=false`，也不把当前研究结果当作用户当时采用的依据。

`load_journal_context`按显式日期/hash调用既有研究owner，绝不回退latest；本地不可变缓存输入明确标`ecs_archive_verified=false`。可选题材引用需date/revision/sha256，仅读同store精确归档并校验；回放引用须具体collection+session/report ID，不扫全量。缺件返回明确missing。该provider存在仍不等于API/UI已经实际调用，须保存实际往返证据。

下一接合是将本笔模式、当前/原计划版本、显式采用的研究与当时事实放在同一视图。首板、接力、抱团可按清楚的语义绑定其研究玩法；MA5趋势、翘板、龙头首阴等没有相同所有者时保持未知或用户显式指定，不自动代入首板。新增模式门禁只有登记所有者、参数版本和适用范围后才可机器判断。

验收用相同个股、不同明确模式以及“改善但仍不合格”“价格正但失败票反证扩大”“资料不足”三组反例；不能用指数红或情绪高抵消本玩法的负反馈。1000亿日终标记不能在上午显示为已完成事实。

### S2-03 市场、板块与个股角色转变（P1）

已有`ThemeCycleReplay`负责题材固定队列阶段与替代，`post_exit_feedback`负责退潮后原核心/后排与大盘比较。context只比较同版本所有者前后输出，记录两个精确日期的市场预期、容量档和玩法支持度变化；角色记录来自原核心/前排/后排关系。单纯日期、价格更新不制造“角色变化”。缺原照、规则升级、题材资料不齐或未来快照不强判转换。

仍需建设的内容是：用户认定的主板块/参照与机器候选分开；角色变化的依据、确认/待定状态与反证；首次扩散和末端补涨的时间顺序；抗跌候选先冻结，再观察企稳后是否主动领涨。这些尚无统一机器阈值，不从“后排”直接推断补涨龙，不把两份日线差异宣称为分钟带动、龙头换位或资金因果。

验收保留一组“板块退潮、原核心仍相对强”的样本和一组“只剩一股强、原后排继续亏”的样本；原名单不得重排为当天幸存者。转变事件能打开前后原件；相同角色仅价格改变时事件数应为零。

### S2-04 预期冻结、三态回证与偏离（P0/P1）

已有库存轮的决策修订会保存旧版本、预期/时限/失效/风险及定义。`append_expectation_check`区分人工评估和已归档数值比较，绑定原决策版本与原验证时点，未到时点或缺实际证据保留unknown。数值比较必须与不可变来源的`value_path`一致，机器比较通过不证明来源真实性、原计划事前性或模式收益。

首买前独立计划已进入本轮代码接合：`freeze_plan`在没有成交轮时保存计划；`bind_plan`将确切版本与明确fill_ids关联，不改原计划身份。既有`trading_watch_plans`的引用要求确切版本和实际内容，另存此次取回/冻结时间，不能把当前可变计划链接当历史证据。

已审合同：冻结时间由服务器生成，不接受用户回填captured/recorded；目标日期在过去、验证时点不晚于冻结、非当时证据或来源时间缺项会阻止`ex_ante_verifiable`。事后绑定记录保持事后性质；只有原计划完整且时点合格、目标日一致、真实冻结严格早于有撮合精度的成交，且每次成交都有覆盖时，才进入事前可核验。该资格证明“计划先存在且可检查”，不证明用户当时确实照计划执行；执行差异仍需单独核对。还须用实际API/UI与保存后重开验证，不凭函数存在勾选完成。

验收覆盖按计划亏损、偏离但盈利、预期成立却因仓位/退出亏损、预期失效但不可成交、未到验证时点以及补记。没有确认条件时不能仅从低开、跌破成本或最终亏损判断违规。

### S2-05 组合风险、加仓过程与跨票链（P0/P1）

已有`calculate_dynamic_target`处理单票风险预算，`calculate_entry_sizing`处理现金与其他计划预留；显式`link_decisions`可保存跨票关系及具体版本。两者不是完整的组合风险路径，资金净流入或时间相近不自动证明“为某票腾钱”“补亏”或心理动机。

本轮新增`analytics.PortfolioRiskService`读取同store持仓、报价、已存风险配置与现金预留，复用上述计算器展示单票风险合计、行业敞口、用户提议情景及仓位预览，并能保存本次真实时点的不可变组合快照供计划引用。这是当前事实接合，仍不能把现有账户配置当核验净资产、把本次快照倒填历史或据此宣称历史组合风险路径已齐。API/UI/ECS保存重读仍须验收。

仍需：当时账户资产/现金/可卖库存快照，单票及用户明确的组合/同题材上限，旧仓和待成交计划占用，跨票关联的来源及可反证状态，加仓前后数量/成本/有效止损/风险变化。账户路径或限制未配置时显示未知，不擅设满仓、70%、5%或30%纪律。共用现有风险配置与计算器，不能在journal再做一套仓位公式。
