# 复盘交互修复

日期：2026-11-03。对应用户六项反馈。

## 填写内容与换行

操作摘要写事实（例如买入数量和成交价）；操作理由写当时判断依据。action由单行input改为textarea，所有叙述字段支持Enter换行并保留内部换行；字段示例只作提示，不填入真实记录。打开表单时焦点落在操作摘要。

## 交割单提示

- 使用完整交易日历确认最近交易日，将已存成交日期与它比较。相同则默认收起；周末回看最近开市日；缺失或重复日历保持待核。
- 点击导入或继续复盘均收起。sessionStorage只记提示折叠，不生成交割单已完整的事实。
- 折叠键包含账户、当前日、最近交易日、最后成交及导入时间。出现新数据或新交易日后重新检查。
- 行情快照等没有成交/财务事实的内部导入批次，不推进交割单的最近导入时点。
- 真实浏览器读取已存成交到2026-11-03，默认收起已验证。日期相同仍不等于全部交易覆盖已确认。

## 目标判断

将“看哪个价格”改为“目标在什么时候达到才算数？”。选项直接说明开盘就达到、盘中最高涨到、收盘仍达到，并附例子：盘中曾有+5%与收盘仍有+5%是不同条件。仅检查行情，实际卖出另列。保留既有metric存储合同与旧数据。

## 复盘标记

复用现有过程复盘确认与fact_digest，不引入另一个完成字段。

- 未复盘：没有过程复盘记录。
- 复盘中：有草稿。
- 已复盘：用户确认完成且当前事实一致。
- 待更新：成交、预期或核验改变，原确认已失效。

列表和详情暴露review_progress；保存本轮过程后立即更新该行标记。完成表示用户已核对该轮，仍可保留未知判断，不授予模式有效或交割单完整资格。

## 上海九百入口

该轮有三次买入和一次卖出，但零条决策补记。原界面的加载提示被列表状态隐藏，进入后成交又被简洁CSS隐藏，造成无反应/空白感。现在点击立即显示正在打开；进入后展示真实成交及“从本笔开始复盘”，不要求先有决策记录。
