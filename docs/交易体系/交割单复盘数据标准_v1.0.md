# 交割单复盘数据标准

版本：1.0 草案。日期：2026年10月18日。

目标是把每笔真实交易变成可追溯、可记录、可分析的交易档案，回答：当时为什么选它、什么条件下买入、买后如何管理、最后赚亏多少，以及执行是否符合事前计划。

本轮交付记录标准、填写模板和可校验的数据合约。自动导入、盘中归档、交易档案页面和归因计算尚未按本标准接入，不能把本文件当成这些功能已经运行。既有研究标签可作客观特征，不代表用户真实交易动机。

## 记录对象

一个交易档案对应账户里一只证券的一轮建仓到清仓。观察、计划、成交、持仓管理和复盘分别留痕。

| 对象 | 记录内容 | 记录时机 |
|---|---|---|
| 观察记录 | 当时观察过的完整名单、加入时间、观察理由、参照对象、买入或放弃原因 | 加入观察池和改变决定时 |
| 交易计划 | 交易模式及版本、买入触发、预期、失效条件、资金与风险约束 | 下单前；来不及填写则标记事后补记 |
| 决策事件 | 首买、加仓、减仓、持有、清仓、放弃及对应理由 | 每次作出决定时 |
| 券商成交 | 真实价格、股数、费用、时间可信度、原始文件及行号 | 人工回写或导入交割单时 |
| 环境快照 | 大盘、板块、情绪、梯队、个股和账户的当时状态 | 决策时冻结；盘后另存一份 |
| 交易结果 | 已实现盈亏、未实现盈亏、整轮结果、仓位变化与持有时间 | 成交后重算；清仓后结算 |
| 复盘结论 | 原计划与实际行为的差异、证据、待验证归因及规则研究 | 收盘或清仓后 |

同一证券同时执行两种模式时，保留证券层面的真实库存；模式层面只有在成交数量明确分配后才分别核算。无法分配时标记混合模式，不能重复计算同一股数的收益。

## 每笔交易需要回答的问题

| 问题 | 最少记录 | 自动与人工分工 |
|---|---|---|
| 为什么交易 | 主模式、买入理由、预期持有周期 | 用户确认；系统可建议标签，不能替用户编造动机 |
| 买点是什么 | 回踩、突破、弱转强、翘板等触发类型；具体可观察条件；实际是否确认 | 用户选择触发，系统附上价格和行情证据 |
| 预期是什么 | 到哪个验证时点，应出现什么；不及预期如何处理 | 用户写简短预案，系统保存原文与时间 |
| 什么时候认错 | 失效条件、计划退出方式、最大允许亏损与仓位 | 用户填写；无计划时如实记无计划 |
| 大盘怎么样 | 相关宽基涨跌、均线与斜率、市场广度、成交额及同时间槽量能 | 自动归档事实，标签附定义版本 |
| 板块怎么样 | 行业与题材的当日归属、板块阶段、核心与跟随角色、同类反馈 | 自动归档候选归属，用户确认本次交易所依据的主板块 |
| 在看谁 | 容量核心、高标、同身位、竞争标的、观察但未买的名单 | 系统冻结观察池，用户注明参照关系 |
| 情绪怎么样 | 涨停、跌停、炸板、昨日强股溢价、失败股与断板股反馈 | 保存原始名单、分母、覆盖率与算法版本；周期判断单独留痕 |
| 梯队怎么样 | 各高度成员、首板与晋级分母、最高连板、晋级率、断板和掉队名单 | 自动保存完整可得名单，不能只留展示用前几名 |
| 加减仓为什么 | 每次操作的独立理由、当时成本、仓位、现金、风险和原逻辑状态 | 成交自动核算，操作理由由用户确认 |
| 最终结果如何 | 含费盈亏、持有期、资金占用、逐批结果、盈利回吐 | 自动计算，缺成本或行情时留空并说明原因 |
| 哪里出了问题 | 入场、持有、退出、仓位、信息及环境变化分别评估 | 系统找差异，用户确认归因，不用盈亏倒推对错 |

## 时间与证据标准

### 当时知道和事后知道分别存

每条环境事实至少记录以下时间与来源：

- `observed_at`：该行情或事实描述哪个时点。
- `available_at`：该信息何时对决策者可用；无法证明则为未知。
- `captured_at`：石论何时实际保存了这条证据。
- `source_ref`：原始来源、记录标识或可定位文件；附内容哈希。
- `evidence_class`：当时归档、历史重建、事后回忆或未知。
- `definition_version`：计算或分类定义的版本。

决策引用的事实必须在决策时已经可用。仅有行情日期，不能证明当时已经获取。盘后成交额、完整梯队、收盘板块强弱和龙虎榜必须属于盘后快照，不能放入上午的买点依据。

盘中量能记录累计额、采样时间、前日同时间槽累计额及过去若干日同时间槽基线。预计全天成交额单独标为估计值，并保存估计方法；不能与收盘实际成交额共用字段。相关数据缺失时不声称已确认放量。

### 原始记录不能被后续结论覆盖

计划、模式定义、决策、快照和复盘均追加版本；修改必须保留原版本、修改时间、作者和原因。成交纠错通过更正记录关联原始记录，重算结果生成新版本。

快照必须能恢复原内容，只保存指向会被更新的“最新状态”的链接不算归档。每个决策绑定实际采用的计划版本和快照编号，不在历史回看时改绑最新版本。

人工补记同时保存实际填写时间和所描述的决策时间。补记可以用于复盘，但不能伪装为事前计划。用户日后确认的历史动机仍属于回忆证据。

### 事实与标签分开

保存指数、均线、成交额、名单等原始数值，再保存由它们生成的分类及版本。不能只留“上升趋势”“放量”“情绪冰点”。

交易模式来自当事人的计划；价格相对MA5、首买相对昨收等属于客观特征。比如用户做翘板，即使公式把价格归到“均线上行的非追涨”，也保留翘板原意，两种信息不能互相覆盖。

板块保存稳定代码、名称、当日成分和分类版本。用户本次交易依据的主板块与证券所属多个行业、概念并列保存。不得用今天的板块归属替换历史归属。

## 模式与买点字典

模式不在建档时被锁死为一组固定战法。每个模式有稳定编号、显示名称、版本、适用环境、入场确认、失效条件和持有周期；允许未知、自定义、混合及待验证。

参考分类可以包含趋势、连板接力、反核翘板、轮动套利等；买点单独记录回踩确认、突破确认、弱转强、开板承接等。它们是录入字典，不是已经证明有效的交易规则。

例如“趋势回踩”需要继续追问：回踩什么位置、何种承接算确认、参照谁、何时算失败。只填一个模式名称可以建立档案，但不足以获得规则回测资格。

2.3万亿元、个股5日均额30亿元、低开5%等，现阶段都应作为有版本的研究假设；保存连续原始数值后再检验，不自动升级为全局交易纪律。

## 成交与盈亏标准

### 原始成交

导入文件保留原件、SHA256、解析版本、原始行号。证券买卖、资金划转、新股、分红和税费分别识别。账户使用内部别名，不在分析导出中包含券商账号、手机号或邮箱。

优先使用券商提供的稳定流水编号。缺少编号时使用来源文件、行号、成交字段及重复出现序号生成候选身份；相同价格、时间、数量的两笔成交可能都是真实成交，不能粗暴合并。跨文件重叠导入需核对券商标识、重复次数及持仓余额；无法确定则待确认，不静默增删。

交割单时间不一定是撮合时间，保存 `time_precision` 与是否核验。不使用未核验秒级时间判断买点先后。公司行为、转托管、期初未知成本、空缺成交及库存冲突应显式阻断相关收益计算。

成交导入先生成对账预览。复盘台账和现有持仓操作台账相互核对，不让历史文件导入再次扣减现有现金或持仓。

### 收益口径

- 一轮交易：同账户、同证券，从已知空仓建仓到再次清仓；期初已有持仓且成本未知时不假定为零。
- 已实现盈亏：采用FIFO匹配卖出净收入与对应买入成本，买卖费用按数量分配。
- 完整清仓轮：买卖净现金流与逐批盈亏必须对账一致；分红和分红税单列，若展示总回报则明确纳入范围。
- 未清仓轮：分别展示已实现和未实现，不混入完整轮胜率；估值标明价格时点与来源。
- 回报率：明确分母。分批加仓时记录累计买入成本、最大资金占用、时间加权持仓及逐批收益，不让循环做T的累计买入额冒充最大占用。
- 按首买日、实际卖出日、最终清仓日的统计分别命名，不互相替代。

“失败后扩仓”先保存事实：加仓前浮盈亏、原逻辑状态、新理由、原计划是否允许、加仓前后风险。是否属于违规扩仓依据当时有效的计划，不能只用买入价格低于成本判定。

## 亏损归因标准

盈利和合规是两条轴。盈利但违反计划仍可有执行问题；按计划承担的正常亏损不直接判为模式错误。单笔结果不足以证明一个模式无效。

| 维度 | 核对问题 | 结论边界 |
|---|---|---|
| 入场 | 当时是否符合已记录的模式、触发及环境要求 | 不能用日后下跌反证当时必然不该买 |
| 持有 | 原逻辑何时失效，有没有按事前条件处理 | 不允许亏损后悄悄延长周期或换模式 |
| 退出 | 是否触发退出，何时可卖，实际何时卖 | 卖后上涨本身不构成卖错证据 |
| 加减仓 | 是否符合原计划，风险是否被扩大 | 区分计划内做T、风险控制与临时摊平 |
| 仓位 | 仓位和金额是否超出当时已记录的约束 | 缺账户信息时不伪造真实仓位比例 |
| 环境变化 | 大盘、板块、情绪何时变化，是否属于可见的新信息 | 不把隔夜意外倒写成买入前已知风险 |
| 信息 | 关键行情、时间、原计划或成交是否缺失 | 允许结论为无法判断 |

归因可以多选，但不自动生成各因素“贡献百分比”。每个判断必须关联计划版本、事件、事实证据和审核状态。系统生成的是候选解释，用户确认后才成为复盘标签；用户确认也不等于因果已被统计证明。

### 如何检验卖点问题

在相同真实入场、费用和数量下，用预先定义且版本固定的退出规则，与实际退出比较。后续另选的规则属于事后研究，不能被描述为用户本来就能执行的原计划。

回放必须检查可卖数量、T+1适用范围、停牌、涨跌停、跳空、手续费与滑点。触及某价不证明该价能成交；分钟内触发顺序无法判断时输出区间或无法判断。

持有期间最高浮盈、最低浮亏和卖后表现可用于诊断，但最高价不是可实现卖价。不能用“如果卖在最高点”计算卖点损失，更不能把“卖后涨了”自动认定为交易本身正确。

## 观察池与回测资格

观察但未买入、准备买但未成交、信号触发后主动放弃，都保留。每次新增、移除、排序和不买原因追加事件。未成交记录不记为真实交易零收益；候选回放单列模拟结果。

完整候选范围有覆盖率：人工自选只能代表这份自选，不代表全市场。没有记录的机会不能在事后宣称当时看过。策略信号全集和人工观察池可以并存，必须说明各自分母。

| 资格 | 需要的数据 | 可以做什么 |
|---|---|---|
| 成交可核算 | 交易与成本完整 | 盈亏、费用、仓位与持有期统计 |
| 决策可复盘 | 有模式或补记、关联证据及时间标识 | 还原决策过程，比较计划与执行 |
| 事前可核验 | 当时冻结的计划、条件、候选和可用事实 | 检验是否按计划交易 |
| 规则可回测 | 机器可判定的规则、历史输入、完整研究范围、成交约束 | 反事实回放与策略检验 |

资格按维度判定，不从一个“完整度总分”推导。允许一笔交易盈亏完整，但动机无法还原；也允许有事前计划但缺分钟数据，无法回放具体卖点。

以后统计同时报告样本量、时间跨度、缺失比例、胜率、盈亏比、中位数收益、净收益、回撤和亏损尾部。回撤必须由完整、对齐的账户或策略净值路径计算，只有清仓盈亏表时不冒充账户回撤。

规则研究先记录假设和版本，按时间划分开发样本与之后的验证样本；跟踪试过的阈值，做相邻阈值和异常交易敏感性检查。个人交易复盘发现的相关性，不直接宣称因果或稳定策略优势。

## 每日使用流程

### 买入前或决定时

系统自动带入证券、当前观察池和可得环境。用户尽量只确认五件事：模式、具体触发、参照对象、下一验证时点的预期、失效与仓位约束。允许语音或一句话，系统结构化后由用户确认。

即兴买入也先留一条最短记录。来不及填时可在之后补充，但自动标记补记时间，不影响真实成交录入。

### 成交后与收盘后

人工回写或导入交割单，先核对重复记录、股数、余额和现金流，再关联计划。没有对应计划的成交进入“待补理由”，不能自动套用最赚钱的历史模式。

每次加仓与卖出有独立理由和快照。收盘自动留存当日完整行情、板块归属、情绪、梯队、观察池和质量报告，用户只处理缺项及实际与预期不符的部分。

### 清仓后

生成交易卡：原计划、各次买卖B/S点、决策时间线、当时市场证据、逐批与整轮盈亏、计划执行差异。用户确认复盘标签；候选归因保留为未确认状态。

## 石论接入位置

2026年10月18日按现有代码核对，以下是可复用的能力，并非确认所有历史日期都有完整数据。

| 现有位置 | 已有能力 | 本标准要补的连接 |
|---|---|---|
| `shilun/trading/timeline.py` | 决策变化追加事件，包含计划与持仓版本、规则轨迹和事实快照 | 关联真实交易档案、用户原计划和原始证据；决策不变化时也需保留关键采样事实 |
| `shilun/trading/executions.py` 与 `order_lifecycle.py` | 成交回写、委托与持仓闭环 | 交割单只读复盘导入、对账去重、零到零分轮；避免重复改变生产持仓 |
| `shilun/trading/execution_production.py` | 场景事实与市场事实快照 | 校验保留范围、可得时间、覆盖率和复盘引用；不能只引用最新文档 |
| `shilun/decision_research/service.py` | 冻结研究预案、模式研究快照与修订 | 关联用户实际采用的版本；研究预案不能直接冒充用户交易理由 |
| `shilun/review/board_ladder.py` | 日期化完整梯队和晋级分母、名单质量说明 | 盘中与盘后分别归档，不用完整收盘名单解释上午的选择 |
| `shilun/review/mood_history.py` | 日级市场情绪归档与缺项诊断 | 保存计算版本；回补结果必须标历史重建 |
| `shilun/market/sector_membership.py` | 日期化板块成分和分类版本 | 将交易所用归属冻结到档案，不随当前分类漂移 |

当前研究数据入口 `shilun/decision_research/data.py` 已明确注明“按行情发生日截至所选日重建；不证明缓存当时已入库”。因此不能靠它把旧交易自动升级为“当时证据完整”的样本。

建议新增逻辑实体：交易档案、观察事件、人工决策事件、原始文件与导入批次、不可变环境快照、成交匹配、复盘修订、规则实验。可用独立集合实现，避免改写现有事实与持仓台账。

## 实施顺序与验收

| 阶段 | 交付 | 必须验证 |
|---|---|---|
| 一 记录闭环 | 交易卡、模式与预期录入、观察池留痕、原始文件导入预览、逐笔对账、快照归档 | 能录下一笔真实交易，标明缺项，清仓后结果可核对 |
| 二 复盘闭环 | B/S点、逐次理由、原计划对照、正常亏损与偏离标签、模式环境统计 | 换设备或改标签后仍能恢复当时原计划；未知项不被填成正常或零 |
| 三 验证闭环 | 固定规则回放、成交约束、候选对照、时间外验证 | 相同输入与版本得到相同结果，盘后信息不会进入盘中条件 |

一期从下一次真实交易开始验收。旧交易保留成交事实和可核验日线；模式、情绪和盘中想法缺失时分别标未知或回忆，不强行补齐。

最低验收场景：

1. 同一交割单重复导入、跨文件重叠及两笔同价同量成交都能正确处理；不重复改变现有持仓或现金。
2. 部分成交、分批加仓、做T、跨日清仓和期初未知成本，不能产生虚假胜率或收益。
3. 买入前计划与收盘后补记外观可辨；补记不能冒充事前已知。
4. 上午决策不能引用下午或盘后才可得的事实；缺少分钟数据时不画伪精确B/S点。
5. 模式改名、阈值变更、板块成分变化和复盘修订后，原版本仍可恢复。
6. 按计划止损但亏损、违反计划但盈利、次日跌停无法卖出，得到不同的执行评估。
7. 相同买入比较不同退出时明确规则冻结时间、可成交性及费用；无法判断时不输出伪精确归因。
8. 观察但未买的标的能查询，但不计入真实成交胜率。
9. 系统中断或数据源失败有覆盖缺口报告，不能让用户误以为全天证据完整。
