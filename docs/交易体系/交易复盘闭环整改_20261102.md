# 交易记录与复盘：预期、仓位与收益对照

本次按用户确认的方向改造现有应用，保留原有成交事实、FIFO、预案与修订所有者，不迁移或批量重写历史交易。

## 主流程

- 复盘 P3 统一为“交易记录与复盘”。成交台账的委托回写、当前库存和历史持仓校准移入折叠的“账户事实工具”。归档库存与当前账户仍分别核对，同笔成交继续显式关联。
- 持仓执行、交易决策及其预案/跟踪退出主导航；旧入口转向复盘对应区域。历史研究预案和跟踪可以从折叠工具显式打开。
- 原“模式收益”转入研究区，命名“市场模式观察”，与个人真实收益区分。
- 日常从待补记录、买前预案、仓位与风险、逐轮复盘、预期核验和模式统计推进。当前账户快照不倒填历史仓位。

## 核验边界

- 仅对已保存的确切决策版本做行情核验。修改预期先追加新版本，不在核验请求里临时替换条件。
- 原预期、核验期限、基准和数值阈值缺项时保留未知。事后补记和当前历史回放保留其性质，不进入事前预测能力的验证分母。
- 预期是否成立、是否遵守计划和是否盈利分别记录。未知、不可成交和计划变更须保留依据。
- 首个收益对照限定同一实际入场、同一数量与下一交易日收盘参考，显示真实收益、规则参考与差额；参考规则不是最高价卖出，也不证明必能成交或模式已稳定。
- 日线或日历缺失、未来数据、费用未知等不能补为零。规则明确后才能扩展全样本模式统计；不从少量交易输出虚构胜率或推荐仓位。

## 验证

实施验证与剩余限制随本次完成记录追加；不以函数存在代替实际接口和页面验收。

### 本轮完成与验收

- 新增 `JournalMarketCheckService.preview/save`：读取原决策确切版本、已存日线和交易日历，支持收盘价/明确基准的收盘涨幅；保存需原预览时点、版本和摘要，来源变化返回冲突。证据通过既有来源归档和预期回证所有者保存，只写 journal 集合。
- 新增 `JournalRuleComparisonService.preview`：固定首笔真实买入完整数量，复用既有 FIFO 实际收益，与下一交易日收盘参考比较。卖出费用率与滑点须显式填写；当前结果是只读历史情景，不是策略验证。
- 新增工作区待办与核验界面，支持保留原文的历史条件补记、原版本行情核验、明确保存、仓位/卖出过程复盘入口和规则收益对照。异步换轮、切版本、改筛选均清除过期结果。
- 全部 journal Python 回归及新 HTTP/页面合同：344 passed、1 skipped；跳过项为未分发的私有原件夹具。Node 新工作区10项、导航整合及原账本真实域交互通过。
- 本机真实页面已读取173轮归档。对九阳原始补记做只读核验，因未明确结构化阈值及基准而保持unknown；未保存或改写用户记录。320/375/414/768/1440宽度无横向页面溢出，隐藏导航不出现，新控件44px。
- Polanyi末次检查：入口归属清楚，真实成交与核验工具可互相到达；补记、未知和收盘参考的性质在主结果中明示，取证原件渐进展开。
- Graphify AST JSON和报告已更新；图规模超过HTML渲染预算，既有graph.html未刷新。

### 当前支持范围

收盘核验不代替“盘中触及某涨幅”的判断。规则参考暂仅下一交易日收盘，费用/停牌/涨跌停约束不全时保留未知；不会用最高价充当卖点。历史仓位与模式仍需用户按证据补齐，当前组合快照不能还原过去净资产。未增加定时核验任务，当前由用户在账本内明确发起；也没有批量改写历史标签或预期。
