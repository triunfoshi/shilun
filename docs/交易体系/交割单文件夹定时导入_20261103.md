# 交割单文件夹定时导入

无券商 API 时，可以每天读取固定文件夹中的 CSV / TSV / XLSX / XLS，但导出仍由券商客户端生成。脚本不会登录券商或进行交易。当前代码与 macOS 18:30 调度模板已准备，**未安装调度、未启用自动写入、未导入任何真实新记录**。

## 首次设置

1. 确认券商导出文件夹。示例推荐 `runtime/trade-statements/inbox`，目前只是待确认路径，脚本不自行创建该目录。
2. 将 `deploy/trade-journal-watch.example.json` 复制成实际配置，先保留 `enabled:false` 和 `profile_confirmed:false`，填入真实 `inbox`。
3. 在项目目录执行：

   ```sh
   ./.venv312/bin/python -m shilun.jobs.trade_journal_watch_job --config deploy/trade-journal-watch.json
   ```

4. 第一次 dry-run 会给出样本SHA、表头与建议映射。逐项确认这份真实样本的工作表、日期、真实成交/发生时间、成交编号（必须文本）、金额与费用的含义，填入 `mapping`、`expected_headers` 和样本的 `profile_sample_sha256`；表头必须逐列完全一致。确认后设 `profile_confirmed:true`。不以建议映射自动授权。
5. 再 dry-run 检查。配置 `enabled:true` 并显式增加 `--apply` 才会导入。启用前再确认实际文件夹和格式。
6. macOS 模板为 `deploy/cn.shilun.trade-journal-watch.example.plist`，默认每天18:30 **仅预览**，没有 `--apply`。确认后可复制成实际任务，换成正式配置路径、添加 `--apply`，再安装。当前没有安装任何任务。

## 自动化边界

- 同一文件重跑通过原件 SHA、账本导入摘要及已有批次幂等处理；相互重叠的导出按稳定券商成交编号接合，不能用同价同量或行号推断。
- 文件仍在写入、表头变化、未识别业务、公式/宏/外链、身份歧义、库存冲突全部停在待核对状态，原件保留，不移动/删除文件。
- 每笔买卖缺稳定券商成交编号，或文件包含分红、转账等财务事件时，转人工导入流程。财务事件缺跨文件稳定身份，不能把重叠文件的同一笔事件重复入账。
- 每次最多扫描100份、每份8MiB；默认文件停止写入60秒后才读取。只读取目录第一层，不跟随符号链接。
- 本地 JSON 回执可用 `--receipt /绝对路径/新的回执名.json` 保存，权限0600，不覆盖旧回执；没有回执文件时输出控制台摘要。调度日志目录需预先设置妥当，避免与原件目录混放。
- “最后一笔成交日期”与“导入时间”分别显示。即使今天导入的文件最后一笔成交是10月26日，也不能证明10月27日至今天没有交易；完整交割覆盖必须另行确认。
- 建仓及每次补仓各自使用对应买入日期的下一交易日作为T+1参考。交易日由已存SSE日历逐自然日核对；日历有缺项/重复时显示未知，不按周一至周五猜测。
