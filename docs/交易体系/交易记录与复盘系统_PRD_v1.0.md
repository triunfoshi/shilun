# 交易记录与复盘系统 PRD

版本：1.0 讨论稿。更新日期：2026年10月19日。

本产品把东方财富证券的真实成交，与交易前的观察、计划、当时的市场证据及后续执行关联起来，形成可以核算、复盘、比较和逐步验证的个人交易样本库。

PRD分为两条线：交易系统先准备模式、预期、失效、仓位、收益及验证标准；产品支持这些标准的日常录入、自动留存、核对和分析。现阶段梳理完整需求，不启动功能开发或数据采集任务。文中“应支持”“新增”均为需求，不代表功能已上线。

上一版[交割单复盘数据标准](交割单复盘数据标准_v1.0.md)是配套草案。本PRD确定业务口径后，再修订字段合约；不能让先写好的字段倒过来限制业务。

## 一 产品目标与范围

### 用户需要解决的问题

1. 当初到底做的是什么模式，为什么从观察名单里选了这只股票。
2. 买点是否真正确认，当时的大盘、板块、情绪与梯队是否支持这笔交易。
3. 加仓、持有和退出分别基于什么理由，过程中是否改变了原来的交易逻辑。
4. 一轮交易最终赚亏多少；亏损是否属于正常风险、入场不符合计划、持有或卖出偏离、仓位失控、环境变化，还是证据不足。
5. 哪些模式在什么环境下更适合自己；提高收益应优先改选股、买点、卖点还是仓位。
6. 新发现的规则是否在之后的新样本中仍成立，避免用同一批历史反复调参证明自己。

### 成功标准

从一笔交易结果，可以回到具体成交、原始文件、当时采用的计划版本和环境证据；从一种模式的统计结果，可以打开所有纳入与排除的交易，复算其分母和收益。

使用者应能区分“我当时的判断”“当时可见的事实”“实际执行”“事后解释”和“规则研究结果”。记录要方便持续使用，不能依赖每次手工抄写行情。

### 范围边界

| 范围 | 本产品要求 |
|---|---|
| 用户与证券 | 先服务个人账户，支持A股及交割单中的ETF等证券；按证券属性处理交易制度，保留扩展空间 |
| 成交来源 | 复用现有人工成交回写，新增东财交割单文件导入与对账；原始文件格式由实际样本确认 |
| 交易动作 | 保存人工决策与真实成交，不接券商自动下单 |
| 邮箱与客户端 | 不以邮件、客户端自动导出或券商接口作为首期依赖；此前暂缓的邮箱接入不恢复 |
| 历史交易 | 可导入与核算，缺失动机、盘中证据和成本分别标记；不要求先补齐所有历史才开始记录未来 |
| 分析与回测 | 完整规划，按数据资格逐步开放；记录功能与策略收益验证分阶段验收 |
| 市场覆盖 | 市场整体留存广度和环境；个股细粒度数据优先覆盖持仓、观察及实际交易证券，不默认采集全市场逐笔数据 |

## 二 交易系统与产品的分工

交易系统回答“如何定义与检验一笔交易”；产品回答“怎样让真实交易按照这些定义留下可用数据”。系统不替用户编造交易意图，用户也不承担本可自动完成的行情抄录工作。

| 层次 | 内容 | 决策与维护者 |
|---|---|---|
| 原始事实 | 成交、行情、名单、板块成分、账户快照及来源时间 | 系统采集，用户核对成交与账户事实 |
| 交易方法 | 模式、买点、持有、失效、退出及仓位规则 | 用户确认，系统提供模板并管理版本 |
| 当次决策 | 本次采用的模式、参照对象、预期与操作理由 | 用户确认；未记录就保留未知 |
| 计算结果 | 持仓、费用、收益、价格特征及规则是否满足 | 确定性计算，保留定义与版本 |
| 复盘归因 | 正常亏损、执行差异、环境变化、待验证解释 | 系统提出证据与候选，用户审核 |
| 规则研究 | 固定假设、比较组、回放、验证样本与结果 | 用户确认研究问题，系统按固定口径执行 |

## 三 交易系统需要准备的内容

以下准备工作不要求一次性给出所有数值。未知项可以留空，但要明确缺失对记录、执行评估和回测的影响。

| 编号 | 需要准备 | 应形成的成果 | 缺失时如何处理 |
|---|---|---|---|
| TS01 | 交易对象、账户和周期 | 账户别名、证券范围、持有周期、期初持仓与成本基线 | 允许记成交，相关仓位或盈亏显示无法核实 |
| TS02 | 模式定义 | 模式卡与版本：赚哪段预期、适用环境、标的角色、持有逻辑 | 记未知或自定义，不按形态强行归类 |
| TS03 | 买点定义 | 触发卡：位置、确认条件、确认时点、价格容忍与取消条件 | 可记描述性理由，暂不做机器规则回测 |
| TS04 | 市场环境定义 | 趋势、量能、广度、资金去向等独立维度及算法版本 | 事实照存，缺失的环境分类保持未知 |
| TS05 | 板块与角色定义 | 当日主板块、板块阶段、核心与参照对象、角色依据 | 保留候选归属，不冒认主线或核心 |
| TS06 | 情绪与梯队定义 | 可核对的名单、分母、晋级与失败反馈，以及周期标签依据 | 不以展示名单数量冒充完整市场统计 |
| TS07 | 观察与筛选规则 | 观察池加入、移除、比较、放弃和未成交原因 | 只研究已记录范围，不宣称代表全市场机会 |
| TS08 | 预期与退出 | 验证时点、正常剧本、超预期与不及预期分支、失效与退出条件 | 无计划如实标记，事后不反写原预期 |
| TS09 | 仓位与加减仓 | 允许风险、初始规模、加仓前提、减仓方式与总约束 | 不给用户擅设仓位；偏离评估暂无法判断 |
| TS10 | 收益与归因口径 | 分轮、成本、费用、回报分母、正常损失与执行偏离标准 | 不能可靠计算的指标为缺失，不能填零 |
| TS11 | 规则验证方法 | 假设登记、比较范围、基准规则、费用与成交限制、验证期 | 只做描述性统计，不宣称模式已验证 |
| TS12 | 日常记录制度 | 哪些时点必须留痕、谁确认、怎样补记、多久复盘 | 产生待补项；不妨碍真实成交入账 |

### 模式 买点与特征分别定义

| 类别 | 回答的问题 | 示例 |
|---|---|---|
| 模式 | 这笔准备赚哪一种预期，采用什么持有逻辑 | 趋势延续、连板接力、反核翘板、轮动套利；均需进一步定义 |
| 买点 | 什么具体变化发生后决定进入 | 回踩收复、突破确认、弱转强、开板承接 |
| 客观特征 | 实际处在什么位置和状态 | 相对昨收涨跌、距离MA5、均线排列、过去5日均额、开盘缺口 |

模式字典允许未知、混合和自定义。现有MA5、红K净流入、结构修复520、周K突破、超跌首板等策略可作为来源或候选，不因为系统已有某策略就把所有交易塞进该策略。

每张模式卡至少有：名称与版本、准备赚的预期、适用与禁用环境、标的角色、入场触发、验证时点、失效条件、持有及退出逻辑、加减仓约束、支持与反对证据、当前研究状态。

“均线上行”不能自动等同完整多头排列；“低开”不能自动等同机会或退出信号；“低于成本买入”不能自动等同违规摊平。这些要分别记录事实，再与该笔原计划比较。

### 环境定义应分层

| 维度 | 需要留存的事实与口径 | 不应混为一谈的内容 |
|---|---|---|
| 指数趋势 | 相关宽基、观察周期、价格与MA5/10/20、斜率、关键位 | 昨日趋势与今日盘中变化；不同指数的分化 |
| 量能 | 市场范围、累计成交额、前日同时间槽、历史同槽基线、盘后实际额 | 盘中估算与收盘实际；绝对量与相对放量 |
| 市场广度 | 上涨下跌家数、涨跌幅分布、站上均线比例及覆盖率 | 少数权重上涨与普遍赚钱效应 |
| 资金去向 | 板块成交占比、增减量、相对强度与核心反馈 | 总额增加与用户所做方向获得增量 |
| 板块 | 当日行业和题材归属、阶段、内部广度、核心与后排反馈 | 静态所属行业与这次交易依据的主板块 |
| 情绪 | 涨跌停、炸板、昨日强股溢价、断板与失败股反馈 | 事实指标、规则生成的周期标签、用户主观判断 |
| 梯队 | 各高度完整成员、晋级分母、晋级名单、掉队名单及反馈 | 盘中暂态与收盘确定；只展示前几名与完整统计 |
| 账户 | 当时持仓、可卖数量、现金、成本与资产时间戳 | 可用现金与总资产；已实现收益与账户净值变化 |

2.3万亿元、个股5日均额30亿元、低开5%等先登记为待验证假设。保存连续原值，允许比较相邻阈值，不直接设成全局交易纪律。

### 预期与仓位需要提前约定

一笔交易至少要说明“到什么时点应看到什么”。低于预期、符合预期、超预期、预期一致和原逻辑失效分别记录，不靠盘后走势重命名。

仓位必须能对应到资金或股数及最大允许风险。实际风险可以因跳空或无法成交超过计划，因此计划亏损上限不等于损失保证。账户基线不完整时，只显示有证据支持的金额，不计算伪精确的账户仓位。

加仓至少核对：原计划是否允许、原逻辑是否失效、是否出现新确认、加仓前浮盈亏、加仓前后股数及风险。只有原计划或已记录规则失效后仍扩大敞口，并有可核验时间顺序，才可标记相应偏离；否则列为待判断。计划内做T与临时摊平分别保存。

## 四 数据对象与生命周期

### 交易档案的数据关系

```text
观察事件与候选名单
        ↓
交易计划及版本 ← 模式与买点定义
        ↓
人工决策事件 ← 当时环境快照及证据
        ↓
委托与实际成交 ← 导入批次与原始文件
        ↓
证券持仓与成交匹配
        ↓
交易结果与过程复盘
        ↓
模式环境统计 → 固定规则实验 → 后续样本验证
```

交易档案、券商委托、成交、证券库存、策略计划和研究样本有独立编号。一个委托可能多次成交；一个档案可能多次加减仓；一个证券可能先后有多轮交易；同一时刻可能有不同模式，但不能重复分配同一股数。

### 三类状态独立管理

| 状态线 | 状态 | 作用 |
|---|---|---|
| 交易进程 | 观察、已计划、待成交、持有、部分退出、已清仓、取消或放弃 | 描述实际进程，实际发生的无计划成交也能建档 |
| 数据资格 | 成交可核算、决策可复盘、事前可核验、规则可回测 | 各维度分别判断，不用单一完整度评分替代 |
| 复盘进程 | 未复盘、系统候选、待用户确认、已确认、有新修订 | 描述结论由谁形成、何时修改 |

“已清仓”不代表证据完整，“已确认”不代表因果已证明，“有计划”不代表已经成交。

## 五 用户完整使用流程

### 盘前

查看前一已完成交易日的环境与同类反馈，加入观察证券，选择或新建模式卡，为计划写预期、触发、失效和风险约束。系统关联当日基线与观察池版本，不要求逐项手抄行情。

### 盘中发现与决策

从选品池、单票分析、板块、情绪梯队或搜索进入记录入口。证券、时间、已知模式和证据自动带入，用户补一句话或确认关键字段即可保存。

最短记录可以只有证券和理由，其余标待补；正式事前计划需要包含模式、触发、预期、失效及风险约束。用户无计划买入不被产品阻止，系统如实显示无计划或补记。

人工决定、系统提示、券商委托和真实成交分别留存，不把系统建议当作用户已执行。所见信息保存来源与可得时间；无法证明当时可见时不授予事前核验资格。

### 成交与持有

在现有成交回写入口保存真实成交并关联计划。导入交割单时匹配已有回写，先展示重复与冲突，再由用户确认；不重复扣现金和持仓。

加仓、减仓、继续持有和改变计划各有独立事件。重复展示的持有提示不用用户反复填写；主动改逻辑或扩大风险必须留存新理由，旧理由保留。

### 收盘与清仓

收盘归档另存当日完整环境，并生成待补、待对账及待复盘队列。清仓完成后生成整轮交易卡，包含原计划、各次操作、B/S点、证据、收益及执行差异。

用户审核候选归因，无法判断就保持未知。周月复盘查看分组结果和反例，把疑问登记成研究假设，而不是立即改全局规则。

### 只有盘后交割单的流程

上传、预览、对账、生成交易档案、关联已有记录、补记理由。已有盘中档案可匹配；未提前观察或记录的证券保留缺口，只用明确标识的历史重建补充客观行情。

盘后导入本身不能恢复上午的想法，也不能保证找回当时完整盘口。产品要让用户看见这条边界，不把数据重建包装成实时记录。

## 六 产品功能需求

P0表示首次真实交易闭环所必需，P1表示基础样本分析与复盘能力，P2表示在数据和定义足够后开放的规则验证能力。优先级不代表某项已开发。

### PF01 模式与买点管理 P0

- 支持模式卡、触发卡、持有与退出规则、风险约束的新增、归档、复制和版本比较。
- 支持未知、自定义及混合；系统建议的模式需用户确认后成为当次意图标签。
- 当次交易绑定具体版本；日后修改名称或阈值不重写历史。
- 规则研究状态分别为未验证、研究中、已有验证结果；状态必须能打开依据，不能由单笔盈亏自动升级。

### PF02 观察池与参照对象 P0

- 从现有选品、单票、板块和情绪入口加入观察，保存加入来源、时间与当时理由。
- 保存完整已记录名单和各次增删事件；可标记主看、同身位、核心、竞争或板块参照等关系。
- 记录未买、未成交、放弃及移除原因；允许未知，区分主动放弃和未出现触发。
- 系统候选全集与人工观察子集分别统计，不能把个人观察池冒充全市场。

### PF03 快速计划与操作记录 P0

- 提供一句话记录和结构化表单，支持随时保存未完成草稿。
- 自动带入证券、时间、计划版本、观察对象及可用环境；用户确认主模式、具体触发、预期、失效与风险约束。
- 区分事前记录、成交后补记、历史回忆与机器重建，展示实际填写时间和描述的决策时间。
- 首买、加仓、减仓、退出及主动改变持有逻辑分别记录；改单与修订保留理由。
- 页面是否打开不决定后台是否归档；无采集服务时显示未覆盖，而不是显示记录已完整。

### PF04 环境与证据归档 P0

- 留存大盘、板块、情绪、梯队、个股和账户事实，记录原值、来源、观测时间、可得时间、保存时间、计算版本及覆盖率。
- 盘前基线、盘中快照与盘后快照分开。每次决策引用具体不可变快照，历史浏览不改绑最新状态。
- 保存真实采用的参照名单与板块成分；名单截断与接口缺项必须可见。
- 可用行情、过期行情、估计值、部分缺失和不可用分别展示。
- 支持证据附件和截图作为补充，保留原件与时间；截图内容不能自动变成已核验市场事实。

### PF05 东财文件导入与对账 P0

- 导入向导包含文件识别、字段预览、交易类型映射、重复匹配、冲突处理、数量与现金核对、确认入库及批次结果。
- 保留原文件、内容哈希、解析版本、原行及批次标识。文件格式支持范围由实际样本验收，不只依赖扩展名判断。
- 处理文件重复、时间区间重叠、已有人工回写、相同价量的真实重复成交、部分成交与数据更正。
- 资金划转、新股、分红、税费、转托管及公司行为与普通买卖分开；未知类型进入待处理，不静默忽略。
- 成交事实即使缺模式也能导入；对账冲突阻止其进入可信汇总，不阻止查看原始记录。
- 支持预览取消、已确认批次的审计更正及重算；不直接删除其他批次共享的事实。

### PF06 成交 持仓与交易分轮 P0

- 复用现有委托和成交入口，匹配导入事实，形成同一份可追溯的成交账本。
- 按账户、证券、库存变化识别从建仓到清仓的交易轮；期初库存与未知成本显式处理。
- 支持部分成交、分批买卖、做T、跨日清仓、卖出后重新建仓。
- 同股多模式只有在股数分配明确时分别核算，未分配时记混合；证券总库存与模式分配之和必须对账。
- 历史导入默认用于复盘与对账；影响当前生产持仓的同步必须单独预览，不能自动重复应用旧成交。

### PF07 每日待办与缺项处理 P0

- 队列分别展示待关联计划、待补理由、待核对成交、快照缺失、待复盘和待确认归因。
- 用户可确认未知或不补，不因表单空白永久无法结算。
- 待办需说明缺什么、影响哪些分析、怎样解决；没有数据不能伪装为零或条件未满足。
- 同一根因产生的重复待办合并，人工忽略保留原因，后续新证据能重新打开。

### PF08 交易档案与B/S回放 P1

- 档案有概览、原计划、操作时间线、行情与证据、收益与成本、复盘修订。
- 日K和可得分钟行情显示每次真实买卖；标记可打开对应计划、理由、持仓变化和当时快照。
- 不具备撮合时间时按日期或可证实粒度展示，不能画成精确分时成交点。
- 支持“只看截至此时已知信息”与“查看后续结果”两种视图；默认明确当前视图，不能静默混入未来数据。
- 支持将两笔成功与失败交易并排比较，比较相同维度和数据资格。

### PF09 预期核对与执行复盘 P1

- 展示事前预期、验证时点实际反馈和用户操作；没有事前预期时单独显示补记。
- 分别评估入场、持有、退出、加减仓、仓位及信息质量，不能只给一个交易好坏分。
- 盈亏结果与计划遵守情况并列，能呈现按计划亏损、违规盈利、环境突变和无法成交等情况。
- 用户可以确认、驳回或修改候选归因，保留来源、证据、版本与待确认状态。

### PF10 统计与分组分析 P1

- 支持按模式、触发、市场趋势、量能、板块、角色、情绪、梯队、月份和执行差异筛选。
- 默认展示样本量、缺失比例、盈利与亏损轮数、净收益、中位数收益、盈亏比及亏损尾部；每个指标有口径。
- 同时提供实际交易总体、可核算子集、记录充分子集，展示排除项及原因。
- 按首买日、实际卖出日、最后清仓日分别提供命名清楚的视图；未清仓不能混进完整轮胜率。
- 筛选结果可下钻到完整交易名单及计算明细；不能只展示最佳分组或盈利案例。
- 样本稀少或集中于单月、单股、单行情段时给出相应提示，不生成稳定优势结论。

### PF11 研究假设与版本管理 P1

- 将“弱市不做大成交额科技票”“次日低开是否应先退出”等问题保存为假设，而非直接变成有效规则。
- 记录研究问题、规则与参数、形成日期、总体样本、比较组、排除条件、目标指标、开发区间与验证区间。
- 保存所有试过的版本和结果，失败实验不能悄悄消失；新阈值不能覆盖当初规则。
- 能从一次复盘结论创建待检验问题，链接支持与反例交易。

### PF12 退出与加仓的反事实回放 P2

- 在固定真实入场与明确仓位口径下比较实际操作和基准规则，输出差异与可执行性。
- 分别支持固定入场比较退出、固定首仓比较加仓、不同候选比较选择；不能在同一个结果里同时改变多个因素后声称只解释卖点。
- 规则登记时间、数据可得时间、费用、滑点、证券制度、停牌、涨跌停和可卖数量必须进入回放。
- 当分钟内路径、盘口承接或成交顺序无法证明时输出范围、无法判断或不可成交，不伪造精确成交。
- 只在亏损单上寻找能改善结果的规则属于探索；验证时必须检查事先约定的完整比较范围及被牺牲的盈利交易。

### PF13 个人交易周期报告 P1

- 支持日、周、月视图，依次回答实际结果、主要贡献、执行差异、环境适配、反例及待验证问题。
- 区分主观意图标签和客观价格标签，不将两者合并成模式胜率。
- 相同输入、口径与版本应能复算同一份报告。导出时包含数据截止、口径、缺口和明细引用。

### PF14 数据质量 运行与备份 P0

- 显示采集运行位置、最近成功时间、来源与覆盖范围；浏览器关闭或Mac休眠后是否继续采集必须可见。
- 中断、限额、源错误、缺日历或估值陈旧产生诊断；可重试补客观事实，但不得把晚到数据标成当时已保存。
- 任务幂等、恢复可续，按账户与交易日处理并发；导入确认和版本保存应有冲突保护。
- 提供原始文件和结构化记录的私有备份、导出、恢复与删除范围说明；删除一个附件或批次不能破坏其他档案引用。

### PF15 AI辅助与人工确认 P1

- AI可以整理一句话为表单草稿、提示记录缺项、总结证据、发现待核验的执行差异、提出研究假设。
- AI不得伪造当时意图、修改原始成交、生成未知行情、替用户确认归因或宣布规则有效。
- AI输出附原文与证据引用；用户确认前保持草稿，不改变事实账本。
- 对外模型传输只使用用户明确选择的内容；账户标识和无关信息默认剔除。记录功能不依赖外部模型可用。

## 七 页面与现有功能适配

不另建一套平行的成交或持仓系统。优先把记录入口放在用户原来做观察、计划和回写的位置，再以统一交易档案串联。

| 现有入口 | 应适配的能力 | 新增或改造 |
|---|---|---|
| 指数复盘 | 选择某一时点的市场证据，关联到交易计划 | 增加“关联证据”，区分盘前基线与盘后结果 |
| 情绪与梯队 | 保存当时名单、同类反馈和参照高标 | 增加引用与快照覆盖说明，不让盘后完整名单进入上午决策 |
| 板块与题材研究 | 选择本次主板块、参照核心及当日归属 | 增加“加入观察”“作为参照”和历史归属留存 |
| 选品池 | 系统候选转为个人观察或交易计划 | 留存候选来源版本、完整范围和人工选择事件 |
| 单票分析 | 新建记录、关联计划、添加截图或事实证据 | 带证券与当前时点进入快速录入，不能自动确认模式 |
| 盘中监控 | 决策时保存证据；观察对象变化留痕 | 采集不依赖页面刷新，监控范围与缺口可查询 |
| 持仓执行 | 对原预期、当前反馈和实际操作进行记录 | 操作前后留痕，逻辑变更追加版本 |
| 成交与持仓 | 真实成交、导入对账、分轮与档案入口 | 复用账本，统一匹配，避免导入与人工回写重复入账 |
| 现有研究预案 | 作为可选择的计划来源 | 用户显式采用后才成为其交易依据，保留采用时间 |
| 数据同步与状态 | 采集覆盖、归档失败、质量和恢复 | 增加交易档案所需数据的覆盖视图 |
| 新增交易复盘入口 | 待办、档案、模式统计、实验 | 在交易相关导航中集中，不复制全部市场研究页面 |

建议交易复盘入口的内容层级：

```text
交易复盘
  今日待办与快速记录
  观察与计划
  交易档案
    单笔概览 / 计划与事件 / B/S及证据 / 收益与复盘
  模式与规则
  统计报告
  规则实验
  导入与数据质量
```

这是功能信息架构草案，不是视觉稿。导航最终形态应在上述业务范围确定后再设计，避免为每个数据对象都增加一级页面。

## 八 自动记录与人工输入

| 内容 | 系统负责 | 用户负责 |
|---|---|---|
| 交易意图 | 提供模板与已有上下文，提示不一致 | 确认真实模式、理由、预期、失效与约束 |
| 参照对象 | 保存观察和引用事件 | 说明为什么看它、为什么选或不选 |
| 行情环境 | 采集、计算、留存来源与时间 | 可补充主观判断，不能覆盖事实 |
| 成交 | 导入、匹配、对账与计算 | 提供文件或回写事实，处理冲突 |
| 操作过程 | 自动关联时间线、持仓及风险变化 | 确认主动操作和改变逻辑的理由 |
| 复盘 | 找差异，列证据与候选解释 | 确认、否认或保持未知 |
| 规则验证 | 固定输入与版本执行统计回放 | 确认问题与比较方式，审核是否纳入交易制度 |

设计目标是常用计划能复用，紧急记录能快速保存，收盘只处理例外和缺项。具体填写耗时与自动填充率在试用中测量，不将未测量的“30秒完成”写成已验证能力。

## 九 数据采集与保存要求

### 留存时点与范围

| 时点 | 范围 | 必须保存 |
|---|---|---|
| 盘前准备 | 市场基线、已持仓和当前观察名单 | 前一完成交易日数据、模式与计划版本、候选和板块归属 |
| 加入或移除观察 | 被操作证券及其参照对象 | 事件、理由、来源页面与当前可得事实 |
| 人工决定或系统重要提示 | 关联证券、市场、主板块、参照对象 | 决策事件与实际采用的快照；两者分别标作者 |
| 实际成交或导入 | 已成交证券与账户 | 原始成交、关联与匹配结果、成交时点可信度 |
| 盘中常规采样 | 持仓和观察证券、相关宽基与市场汇总 | 满足所选买点粒度的行情与缺口；首期以闭合5分钟K为基础候选粒度 |
| 收盘完成 | 全市场环境及当日实际覆盖范围 | 完整可得的日级事实、情绪与梯队、分类成分、观察和计划最终版本 |

采样频率必须结合当前API权限、限额、延迟、存储与所选买点验证，不能承诺所有盘中信息每秒可取。需要逐笔盘口才能判断的模式，在只有5分钟K时显示无法验证。

采集应由可持续运行的后台任务负责，浏览器只读写用户记录。采集在本机还是常驻服务运行、如何适配Mac休眠、数据存在哪里与保存多久，属于上线前必须确定的部署项，本PRD不自动作出迁移或开通决定。

### 时间与版本

每个事实保留观测时间、可得时间、实际归档时间、来源、质量和定义版本；计划、决策、标签及复盘都能恢复原版本。回补只改善可重建事实覆盖，不改变“当时是否已保存”的状态。

按交易所日历处理交易日，记录带时区时间；跨市场证券按各自制度处理。修订使用新增版本与更正关系，不能通过更新时间覆盖原始事实。

持久归档应保存必要原内容与校验信息；指向会被覆盖的“最新快照”的链接不足以恢复历史。

### 保存期限与成本

原始文件、用户决策、关键快照与修订记录作为长期档案。高频行情、截图等大体积数据按可回测需要制定保留与压缩策略；保留期缩短前先说明会丧失哪些回放能力。

全市场环境汇总与持仓观察证券的细粒度数据分层保存，避免为有限个人复盘默认存储全市场逐笔。容量预算、备份周期与恢复目标在技术设计和试用后确定。

## 十 账本与收益口径

| 指标或对象 | 产品口径 |
|---|---|
| 原始成交 | 券商事实为对账依据；人工回写与券商记录匹配，不重复使用同一成交 |
| 一轮交易 | 同账户同证券，从可核实的建仓到再次清仓；期初已有持仓不能假定空仓 |
| 已实现盈亏 | 采用明确版本的FIFO成本匹配，含买卖交易费用；与完整清仓净现金流对账 |
| 未实现盈亏 | 剩余持仓按明确时点价格估值，独立于已实现结果 |
| 分红与公司行为 | 单列现金与库存变动，若提供含分红总回报则明确纳入范围和税费 |
| 回报分母 | 标明累计买入成本、最大资金占用或其他定义；不能混用循环做T的累计买入额与最大占用 |
| 胜率 | 以已清仓且成本可核算的完整轮为一种默认视图，分母和排除清单必须显示 |
| 同股多模式 | 股数明确分配后才分别统计；否则为混合或未分配，不能重复记收益 |
| 账户净值与回撤 | 需要完整资产路径及资金流，缺失时只给实际支持的交易统计，不冒充账户回撤 |
| 机会成本与未买样本 | 单列模拟观察结果，不作为真实已实现收益或真实交易零收益 |

当成交缺失、顺序冲突、期初成本未知、公司行为未处理、价格口径异常或费用不明时，给出受影响范围及待处理状态。精确收益计算以可核实成本为前提，不因为页面需要显示数字而补默认值。

导入确认、匹配与对账应有一致提交边界。一个批次失败不能导致部分成交进入可信收益、部分仍待处理却没有说明。

## 十一 亏损归因与卖点检验

### 先核对过程 再研究原因

| 情况 | 应记录的判断 |
|---|---|
| 按原计划止损并亏损 | 正常风险兑现候选；单笔不能说明模式无效 |
| 入场条件尚未确认就买入 | 入场偏离候选，关联当时规则与事实 |
| 退出已触发且可以成交却未按计划处理 | 退出执行偏离候选，检查提示、确认及真实成交时间 |
| 退出触发但因制度或流动性卖不出 | 记录不可成交，不直接归责为未执行 |
| 原逻辑失效后继续扩大风险 | 加仓或风险偏离候选，需核实失效与加仓先后和原计划 |
| 卖后上涨 | 只先记录后续价格路径，不自动判卖错 |
| 违反计划但最后盈利 | 盈利与执行偏离并列，不能因此证明行为合理 |
| 没有原计划或当时数据 | 归因为信息不足，允许事后研究但不能冒充事前核验 |

入场、持有、退出、加减仓、仓位、环境变化和信息缺口可以同时存在。系统不自动把亏损金额按百分比分摊给它们；金额分解与因果解释必须区分。

### 怎样比较实际卖出和规则卖出

固定同一笔真实入场，选定事先登记的退出规则，按可得行情与证券制度回放。明确剩余持仓、成交限制、费用、滑点、资金占用及回放终点，输出规则收益减实际收益。

日后才想到的退出法标为事后探索。用于验证时，不能只选择最终亏损的交易；必须同时检查完整预定范围及因此少赚、提前退出或无法成交的情况。

持有期间最大有利或不利波动、卖后若干日表现只作诊断。未来最高价不是可实现卖价，分批交易的路径指标还需区分固定首仓与真实动态仓位。

## 十二 统计分析与规则验证

### 第一阶段必须能回答的分析问题

1. 相同意图模式，在不同大盘趋势、量能与情绪环境下的实际结果分别怎样。
2. 相同客观价格特征，在不同真实交易模式中是否表现不同。
3. 原计划遵守与偏离的收益、亏损尾部和资金占用是否有差异。
4. 首买、加仓和最终清仓的结果分别怎样，是否存在小赢多次、大亏少次。
5. 盈利是否集中于少数个股、月份或行情段，移除最大赢家和最大输家后结论怎样。
6. 一笔交易失败，是原逻辑未兑现、入场条件不满足、持有与退出改变了预期，还是资料不足。

这些首先是描述性问题，比较结果不自动证明某因素造成盈亏。

### 规则实验必须登记

研究问题与形成日期、版本、具体参数、全体研究范围、比较基准、排除项、目标指标、费用和成交假设、开发样本、之后的验证区间，以及已经尝试过的版本。

对“弱市且量能不足时是否回避大成交额科技票”的实验，应分别保存市场趋势、市场量能、个股连续成交额、行业题材和入场类型，比较完整交叉分组；不能把几种条件混在一起只看某一笔输赢。

对“次日低开是否先退出”的实验，先明确低开相对昨收、首买价还是含费成本；触发检查时点、可成交性、是否再进入与费用均固定。不能在不同交易上事后选择最有利基准。

### 验证与发布

探索结果进入待验证，不立即成为执行纪律。用随后新样本或预先隔离的验证区间检查，报告样本量、缺失、时间集中、极端值、阈值敏感性及比较方式；不规定一个通用最小交易笔数便宣称足够可靠。

执行规则的新增、停用或升级有独立确认记录和生效时间。历史交易继续绑定旧版本，报告可以显式用新规则重算，但不能改写当时采用的规则。

## 十三 数据资格与功能开放条件

| 资格 | 条件 | 开放功能 | 不足时保留的能力 |
|---|---|---|---|
| 成交可核算 | 库存、成本、费用与更正可核对 | 实际收益与资金统计 | 原始文件查看、待对账队列 |
| 决策可复盘 | 有意图或补记，操作与证据能关联 | 原计划与过程回顾 | 成交核算与缺项说明 |
| 事前可核验 | 原计划及使用证据在当时已留存，时间可证明 | 是否按计划执行的判断 | 明确标识的事后回忆或重建分析 |
| 规则可回测 | 规则可判定，历史输入与研究范围明确，成交约束可模拟 | 固定版本反事实与验证 | 描述性结果和待验证假设 |

是否满足这些条件按具体问题判断。例如日线可以支持某种收盘规则，但不足以验证分钟内先后；主观判断可以复盘，不因没有机器条件而被丢弃。

## 十四 非功能与交互要求

- 记录入口保持同一套关键字段，支持草稿、恢复、键盘录入及重复使用模式模板，避免各页面产生不同的交易理由格式。
- 数据不足或API不可用时，真实记录仍能保存；显示缺失与影响，不能把失败显示为正常零值。
- 历史加载使用归档，不在打开档案时临时拉取当前数据并覆盖旧判断。
- 关键保存与导入有幂等、版本冲突保护及明确结果；网络中断后能区分未保存、已保存和待确认，避免重复提交。
- 默认私有、账户使用别名；日志与导出不泄露券商账号、密钥和不相关个人信息。权限与原始附件访问应随部署方式设计。
- 规则与盈亏计算可复算；用户可导出原始记录、结构化档案、版本和口径，不被某个页面绑定。
- 备份和恢复用实际恢复演练验收；记录保存时间、采集覆盖与数据版本独立展示。
- 不依靠颜色区分状态；时间、金额、百分比单位清楚；自动摘要不能遮住原文和反例。

## 十五 分期与依赖

| 阶段 | 目标 | 纳入能力 | 进入下一阶段的依据 |
|---|---|---|---|
| 需求准备 | 完成业务定义和数据可得性确认 | 模式卡与环境字典草案、样本文件、期初账本、源与采集部署方案 | 核心定义可填写，关键来源与缺口清楚 |
| 一期 真实记录闭环 | 下一笔真实交易能留痕并核算 | PF01至PF07、PF14基础能力；可读的基础交易卡 | 计划、证据、成交、库存和清仓结果可追溯，不重复入账 |
| 二期 复盘分析闭环 | 能比较过程与结果 | PF08至PF11、PF13、PF15 | 原计划不被改写，统计可下钻复算，归因有证据且可保持未知 |
| 三期 规则验证闭环 | 用新样本检验具体规则 | PF12、规则实验验证与执行规则生效管理 | 输入时点、比较范围及成交模型通过相应验收 |

即使一期样本还少，记录闭环也可以完成；只有收益统计好看而记录不可追溯，不能算完成。

## 十六 验收场景

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC01 | 一笔事前计划到清仓 | 能恢复原模式、预期、快照、全部成交与含费结果；引用均可追溯 |
| AC02 | 无计划买入后盘后补记 | 成交可入账；原填写时间保留，不能标成事前计划 |
| AC03 | 同一文件重复导入 | 不新增重复成交，不重复改变当前现金和持仓 |
| AC04 | 两个文件时间范围重叠 | 正确匹配已存在记录；不确定项进入冲突预览 |
| AC05 | 两笔同时间同价同量真实成交 | 不能因字段相同误删其中一笔；按券商身份与重复次数核对 |
| AC06 | 手工回写后再导入券商文件 | 两份来源关联同一事实，可信收益只记一次 |
| AC07 | 部分成交 分批买卖与做T | 委托、逐笔成交、证券库存与匹配盈亏一致 |
| AC08 | 期初持仓成本未知或成交缺失 | 标出受影响范围，相关收益不补零或虚构成本 |
| AC09 | 同股两种模式 | 分配股数不重复；未明确分配时按混合或未分配展示 |
| AC10 | 计划 模式与板块定义修改 | 历史仍能恢复原版本；新统计显式显示重算口径 |
| AC11 | 上午决策与盘后完整梯队 | 上午视图不引用盘后才可得事实；盘后材料独立展示 |
| AC12 | 页面关闭或Mac休眠 | 运行状态与实际采集行为一致；中断区间显式缺失 |
| AC13 | 缺分钟行情或真实撮合时间 | 不显示伪精确的分时买卖点，不强判盘中先后 |
| AC14 | 按计划止损但亏损与违规盈利 | 盈亏与执行评估能独立表达，不从结果反推过程 |
| AC15 | 失效后加仓与计划内做T | 能按原计划、风险变化和证据区分；证据不足时待判断 |
| AC16 | 次日低开或无法成交 | 回放检查参照基准、证券制度与可卖数量，不假设触价必成交 |
| AC17 | 卖后上涨 | 只记录后续路径；判卖错须额外规则与过程证据 |
| AC18 | 观察但没买 放弃与委托未成 | 可查询过程，不混进真实成交胜率和零收益交易 |
| AC19 | 同一分组按不同日期归属 | 首买日、实际卖出日、清仓日口径可辨且各自复算 |
| AC20 | 只筛亏损单改卖点 | 明示探索范围；正式验证同时纳入预定总体及受损赢家 |
| AC21 | 修订数据或AI生成归因 | 保留旧版本；AI建议未确认，不直接改成交或生效规则 |
| AC22 | 任务中断 导入失败与备份恢复 | 数据状态可判断、可续传和恢复，未出现静默部分入账 |
| AC23 | 历史交易动机缺失 | 客观事实可重建，动机保持未知或回忆，不伪造用户意图 |
| AC24 | 相同输入版本重算 | 相同规则、范围和费用产生相同结果，能打开底层明细 |

先用构造场景验算账本、版本、时间与边界，再用经过用户核对的一小批真实交易走通流程。上述是未来验收要求，本轮未运行这些功能场景。

## 十七 产品指标

| 目标 | 指标定义 | 衡量注意点 |
|---|---|---|
| 能持续记录 | 有效记录交易日、快速记录耗时、待补项处理时间 | 需要试用基线，不先给未经验证的达标数 |
| 成交可信 | 已核对成交比例、重复与冲突处理情况、库存及现金差异 | 金额可核实的清仓轮应对账到分；异常不能靠四舍五入掩盖 |
| 证据及时 | 实际归档覆盖率、关键决策证据可用率、事前计划占比 | 当时归档与后来补齐分别计算 |
| 复盘有用 | 已复盘轮数、证据支持的执行差异、未知原因分布 | 确认率不是越高越好，不能为提高指标强行归因 |
| 分析可靠 | 可核算样本占比、统计下钻可复算率、排除项透明度 | 数据充分子集不能冒充全部交易 |
| 规则可验证 | 有完整登记的实验、验证期结果、版本追溯 | 盈利提升是后续观察结果，不是产品上线保证 |

## 十八 评审时需要确定的事项

以下是PRD待定项，不阻止继续梳理需求，也不擅自采用旧项目配置作为当前账户真实参数。

| 编号 | 待定事项 | 需要准备 | 影响 |
|---|---|---|---|
| Q01 | 首批认真记录的模式 | 用户实际使用的少数模式及成功失败样本 | 模式卡、字段与规则粒度 |
| Q02 | 首选记录时机 | 盘前建计划、临盘快速记录和盘后补记的实际习惯 | 入口、提醒与事前覆盖率 |
| Q03 | 预期与失效的表达 | 每种模式的验证周期和可观察条件 | 是否能核验过程与机器回测 |
| Q04 | 当前账户基线 | 账户别名、期初持仓、成本、资产、现金及可信时间 | 库存、风险和收益资格 |
| Q05 | 仓位与加减仓约束 | 用户自己的风险预算、加仓前提、计划变更边界 | 执行偏离判断，不能由AI代定 |
| Q06 | 东财文件支持 | 真实导出样本、字段、时间可信度与覆盖日期 | 解析、重复匹配与对账 |
| Q07 | 采集与保存位置 | 可持续运行的设备或服务、现有后台复用情况 | Mac关闭后的连续性、权限与备份 |
| Q08 | 细粒度行情能力 | 源权限、历史保留、实时延迟与额度 | 能否判断具体买点与卖点 |
| Q09 | 情绪梯队的完整性 | 盘中与盘后名单来源、覆盖与时间 | 分母、周期标签与反事实资格 |
| Q10 | 交易轮和多模式分配 | 是否存在同股多模式，如何确认股数归属 | 个人模式收益是否可核算 |
| Q11 | 复盘频率与AI权限 | 日周月使用习惯，哪些内容可交给模型 | 待办、摘要与隐私设置 |
| Q12 | 第一批规则实验 | 最优先想验证的问题和比较标准 | 先收集什么、何时能开始验证 |

评审先确定Q01、Q03、Q04、Q06至Q09，保证第一期有真实记录与可用证据；其余规则可以保持未验证，随新样本完善。准备工作不能演变成要求用户先写完一套完美战法才允许记录。
