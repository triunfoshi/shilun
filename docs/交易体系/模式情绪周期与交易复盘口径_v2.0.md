# 模式、情绪、周期与交易复盘口径 v2.0

日期：2026-10-26。机器目录版本：`trade-journal-definitions-v2`。

本文规定交易样本账本的字段含义、跨页面引用和历史迁移方法。机器词典唯一入口是 `shilun/trade_journal/definitions.py`。它描述已有规则及明确标注的人工概念，不增加执行阈值，不改变现有策略启用状态，不用文档代替运行验收。

## 1. 每笔交易分开记录的九个轴

| 字段 | 回答的问题 | 例子 | 不能代替什么 |
|---|---|---|---|
| 模式 `mode.*` | 用户本次准备赚哪一段钱 | MA5趋势、首板套利、连板接力、核心抱团、轮动、反核翘板、龙头首阴 | 不能从涨跌、成交价或后来盈利推断 |
| 触发 `trigger.*` | 当时出现什么才出手 | 回踩收复、突破、弱转强、翘板承接、E1—E8、五买点形态 | 有形态不等于用户采用了对应模式 |
| 动作 `action.*` | 本次怎么处理真实库存或观察 | 首买、加仓、减仓、清仓、持有、做T、放弃 | 做T是管理动作，不是另一份可重复计收益的库存 |
| 环境 `environment.*` | 当时市场与目标玩法处于何种背景 | 指数姿态、量能、风格、容量档 | 指数红不等于所做模式赚钱；弱市不保证有抱团 |
| 情绪等级 `emotion.*` | 所选收盘日的强弱水平 | 冰点、普通、活跃、亢奋、待确认 | 分数不是上涨概率，也不等于周期阶段 |
| 周期 `cycle.*` | 在指定范围与时间顺序中处于哪一段 | 人工试错/主升/震荡/退潮；固定队列发酵/加强/分歧/回流/退潮 | 不同周期轴不能同名合并，不按固定天数轮转 |
| 角色 `role.*` | 个股相对谁承担什么功能 | 情绪龙头标签、容量中军、趋势核心、核心/龙头候选、跟随 | 最高、最大、早封板或名人持有均不独立证明真龙头 |
| 证据 `evidence.*` | 何时、通过什么信息得到判断 | 当时归档、历史重建、事后回忆、未知 | 用户后来确认仍是回忆，不升级为事前计划 |
| 执行策略 `strategy.*` | 实际绑定哪套可运行规则 | `manual`、`ma5_v0_2`、`e7_oversold_overnight`及注册版本 | 不能把用户主观模式自动绑定默认MA5 |

客观特征单列 `technical_feature.*`，例如价格距前日MA5、均线排列、是否收盘涨停、抗跌。证券用代码作身份、名字作显示；同一证券不同轮次可以有不同模式。多个模式只有明确分配股数后才能分账，否则是混合/未分配。

`mode.unknown`表示不知道；`mode.manual`表示用户明确采用自定义模式；`strategy.manual`是已有不生成自动买点的执行适配器。三者不得互换。未收录词保留原文和未解析状态，不能默认为已知模式。

## 2. 单一机器目录和引用契约

```python
from shilun.trade_journal.definitions import (
    get_definitions, get_definition, validate_definition_references,
)

catalogue = get_definitions()  # version, categories, definitions, boundary
ma5 = get_definition("mode.ma5_trend")  # 未知ID返回None，不按中文名称猜测
checked = validate_definition_references(
    [{"id": "mode.ma5_trend", "rule_version": ma5["rule_version"]}],
    expected_category="mode",
)
```

每条定义包含：`id`、`label`、`category`、`axis`、`definition`、`status`、`rule_version`、`scope`、`formula`、`numerator`、`denominator`、`unit`、`window`、`time_basis`、`missing_policy`、`sources`、`limitations`、`aliases`、`parameters`。定性项的分子分母为null，不能为显示整齐补一个伪公式。

来源至少含仓库相对路径、符号/章节、版本。未独立版本化的旧函数由词典版本描述当前口径，保存样本时还应绑定完整定义快照及来源内容身份，不能伪称原模块有版本。

`parameters`取规则所有者的默认配置快照，不保证等于某次运行的有效配置。允许调用方覆盖参数的引擎还须记录当次有效配置、覆盖来源与内容身份；词典快照不能代替运行配置，也不改变开关。

`validate_definition_references`返回`valid/version/resolved/errors`；未知ID、类别错位、规则版本不符分别报错。空引用列表只表示没有待解析引用，不表示成交、事前或回测资格通过。

历史记录冻结实际使用的定义完整快照、ID与规则版本。后来更名或算法升级不改写历史。当前词典无法解析旧版本时保留旧快照，要求显式迁移/重算；不能把旧记录改绑新定义来消除冲突。

## 4. 四档情绪与四段周期不得混合

P2现有收盘情绪：`cold`为分数<30；`normal`为30—59；`active`为60—79；`hot`为≥80。等级由涨停供给、昨日涨停反馈、连板高度、上涨广度、量能、接力扩散与独立跌停风险扣分组成；不足资料为`pending`。使用原分值和规则版本，不从20/30日窗口重新分位，不能把某天改成另一个等级。

人工的试错/主升/震荡/退潮是时间顺序解释，必须指定范围和依据，目前没有一个统一机器阈值。主升也可能出现当日分歧，冰点也不证明次日必修复。不得写“冰点=试错、亢奋=主升”。

固定题材队列采用现有`CycleRules`：近3交易日核心及后排累计反馈；连续弱3次，或15%回撤预警伴连续弱2次才进入其退潮分支；分歧后连续强2次才修复。具体参数始终从`theme_rules.rule_config()`读取。这是题材状态机，不是个人止损比例或市场退潮固定时长。

## 5. 容量、量能和1000亿的时点

1. `market_amount_cny`为元；来源日线`amount`原单位为千元，须转换后逐股去重。当前`market_turnover`统计沪深北A股，含ST，不重复加指数/ETF成交额。依来源覆盖报告缺项，不能拿几个重叠指数直接相加。
2. 既有MA5容量规则：全日总额<2.1万亿时证券7日均额<50亿；2.1万亿至2.3万亿（含2.3）时<100亿；>2.3万亿不设该均额上限。窗口是完整交易日，缺日不补零。这里的50/100亿是证券成交额，不是市值。
3. 旧P2姿态中另有300亿市值及2.1/2.3万亿权限，且边界写法与MA5模块不完全相同。保留原版本，不擅自把两者合成一条全局许可。当前账本只记录采用哪条规则。
4. “增加1000亿”是**当日全日实际额减前一交易日全日实际额≥1000亿元**的旧P2标记。不是10:00比昨日全天增加，也不是预测全天增额；日终以后才完整可知，不单独授予开仓。
5. 盘中量比用同一采样时点、相同市场范围的累计额对比。预计全天额单列估计方法、采样时间与误差，不能复用实际全日字段。没有同时间槽基线就标无法确认放量。

固定额门槛均为已有研究规则，尚未由个人交易记录证明为最优。不得把心法中的历史点位、比例或个别案例加成新的执行阈值。

## 6. 核心、龙头、前后排和角色变化

强股资格规则复用`core-qualification-v2`：新连板段首板起10交易日内，本段完成三连板且累计至少5次收盘涨停；走势首板与资格段首板分别保存。停牌或不可得日不得压缩窗口；15%收盘回撤只是提醒。

资格核心、旧P2的互斥角色、板块研究按综合分排序的总龙头候选是不同口径。保留各自代码、版本、截止日和来源。公开页面应使用“候选/价格资格/观察”来限定证据，不用“真龙”给收益担保。

题材扩散排除重复核心，归因必须有当日成分及涨停原因支持；原因未知不等于零扩散。同一天/不同题材的同一股票去重规则必须明确。当前准入是近3交易日至少2只独立跟随、跨至少2日，复用`SelectionRules`，不能把数量直接解释成主线级别。

固定原核心/后排用于评价后来失败，不能为展示当前强者而重写。新的角色变更另加事件：原角色、新角色、参照、时点、支持/反对证据与确认性质。抗跌只描述指定下跌窗口；抗跌后领涨须先冻结候选再观察后来企稳阶段，尚无统一机器阈值，记录为研究假设。

## 7. 样本分母、窗口和收益必须一起显示

| 指标 | 分子/分母和单位 | 禁止混用 |
|---|---|---|
| 次日开盘溢价 | `(T+1开盘/T收盘−1)×100`，百分点；名单在T形成 | 不是T+1买入者的收益 |
| 次日收盘反馈 | `(T+1收盘/T收盘−1)×100`，百分点 | 不是含费、滑点与成交限制的真实收益 |
| 红K | 收盘>同日开盘，布尔 | 不等于相对昨收上涨，也不否定已兑现的开盘溢价 |
| 晋级率 | 冻结前日队列中次日收盘封板数/该指标有效可观察数，比例 | 一字和可换手梯队分列，缺行情不直接当失败 |
| 炸板率 | 当日触板未封数/(同范围收盘封板数+触板未封数)，比例 | 涨停池开板后回封次数不能冒充炸板未回封分子 |
| 正反馈广度 | 首板看正开盘溢价；接力/核心看正收盘反馈的有效比例 | 不是同板块所有成员上涨比例 |
| 明显亏损尾部 | 现有研究用≤−5%切片，分母按玩法分别固定 | 不是个人止损线或统一生态合格线 |
| 实际已实现盈亏 | FIFO匹配卖出净收入减含费买入成本，元 | 现金净流入、券商摊薄成本、未实现盈亏不能互替 |
| 整轮成本回报 | 完整轮含费盈亏/累计含费买入成本 | 分批做T的累计买入成本不等于最大资金占用 |
| 真实胜率 | 盈利完整可核算清仓轮数/同范围全部完整可核算清仓轮数 | 开仓轮、未知成本、中签、模拟未买不混入主动交易分母 |

现有玩法比较用近期3/5个完整交易日，对紧邻且不重叠的此前10交易日；每日最少3有效样本及95%覆盖、基准至少8/10日达标等门槛复用`playbook_assessment.POLICY`。报告样本是股票日，不宣称同一批股票人人改善；缺失日保留，不跳过找替代；比较改善与当前支持度，不拿累计收益跨玩法选冠军。

每个统计保留：形成日/观察日、范围、原始队列、去重键、有效数/总数、覆盖率、单位、取值时点、分组版本、排除清单和缺失原因。零分母结果为未知或无样本，不是0收益、0风险或100%安全。

账户原始证券始终保留ST/ETF/IPO及其他现金事件。研究排除规则不得删除真实成交。`research_scope`的题材/核心筛选与打板池来源可比范围不同，必须分别保存；历史当前名称不能证明过去ST状态。

## 8. 时间、证据、交易轮和资格

每条事实至少有`observed_at`（发生时点）、`available_at`（可得时点）、`captured_at`（保存时点）、来源定位/内容身份及定义版本。只有行情日期不能证明当时看过；盘后龙虎榜、完整收盘名单、全日成交额不进入上午决策依据。

券商发生时间未必是撮合时间。保存原时间及可信度，未经核验不画秒级B/S点。真实成交以原始来源及行号/稳定身份对账，相同时间价量可能是两笔，不能粗暴去重；跨文件重叠不能重复扣现金或持仓。

同账户同证券从可核实空仓到再次清仓为一轮；部分卖出后仍有新买库存则不结轮。旧文件未清仓的金健米业必须接后续成交再结算。期初未知成本、公司行为、库存冲突和缺失成交阻断受影响的收益，不补零成本。

四项资格独立：

- `qualification.accounting`：成交、库存、成本、费用可核算。
- `qualification.decision_review`：用户意图/补记、操作与证据可关联。
- `qualification.ex_ante`：当时冻结的原计划和所用事实有可得时间证明。
- `qualification.rule_backtest`：可判定规则、历史输入、完整范围、费用与可成交模型齐备。

每项输出`eligible`和具体`reasons`，并绑定其`definition_ref`。不采用一个完整度总分替代；成交盈亏完整不代表动机可还原，用户补记完整也不代表事前可核验。

观察范围用`scope.manual_watchlist/strategy_cohort`，观察状态用`observation_state.*`。前者是实际保存的个人子集；后者只有通过`freeze_strategy_cohort`与精确研究版本/日/hash及完整成员逐项核对，才表示“相对于该研究群体完整”。成员失败、空分母或暂未买入均不得删掉。后续未买/未触发/未成交是回指父观察的追加事件，不修改原群体，也不列入真实交易零收益。历史daily含后来反馈事实，只能标历史重建；完整群体不自动获得事前或回测资格。

独立计划通过`freeze_plan`在首买前保存，不要求已经有库存轮。每次修订有新的实际冻结时间与内容身份；引用既有可变计划也从本次真实冻结时刻算起。成交后来经`bind_plan`明确关联原版本和成交身份，绑定事件本身不倒灌时间。事前可核验与实际是否照计划执行仍是两项判断。

预期复盘核验另用`expectation_check.supported/refuted/unknown`，分别为获支持、被反证、无法核验。核验须关联原预期、原窗口和所用事实，保留核验类别、操作者及时间。默认`evaluation_class=manual_assessment`，人工选择“获支持”不会升级为机器核验。`numeric_comparison`只有实际数值与不可变来源的`value_path`一致、窗口和可得时点齐备，且冻结条件可比较时，才由服务设置`machine_verified=true`；它仅证明数值比较，不证明来源真实性、原计划事前性或策略有效。缺项或未到验证时点保留未知。该轴与`expectation.*`的历史分布比较不同，也不代替四项样本资格。

## 9. 历史材料如何迁移

1. 保留旧`episode_id`、来源行、数量/费用/盈亏及原始技术标签。用户模式未知就保持未知，不以“上升趋势且靠近5日线”代填MA5意图。
2. 国芳9/16的用户原意翘板覆盖模式命名，原技术特征并存；不能重复追问已补的原意。哈药扩仓和东山弱市抄底分别关联各次决策，不能都压成“低开必须割”。
3. 新华传媒10/19已有龙头首阴、金健已有抱团修复/做T、新易盛及风华已有外部交易参考与后续管理补记，继承其原文和事后性质，只追未明确的触发、期限与风险上限。
4. 风华10/21的40.80是盘后选择，不填成原计划价；“全天主动上攻”是盘后表述，不能假定买入时已知道全天。记录中的时点冲突保留两边事实与未解决状态。
5. 旧v5文件名“核对”不等于人工确认；统计计算、报告转述、原始用户补记的证据类型分别标注。盈利轮和亏损轮、加仓和未加仓同时保留，不只补大亏案例。

## 10. 验证、版本和心法边界

词典测试须核验ID唯一、源文件/版本可定位、未知不会降格为manual、各轴不混用、策略身份与现有注册表一致、核心与题材参数与规则所有者一致、情绪边界及1000亿日终语义一致。测试通过只证明口径契约，没有验证交易收益。

蟹老板与《48位游资》材料用于提出环境、预期、确认、失效和成功失败配对的问题。它们不是当前制度来源或策略有效性证明。“龙头必给退出机会”“满仓”“普跌后80%反弹”“两日无风险”等不进入默认纪律。新增参数必须独立登记假设、形成日期、完整研究范围及时间外验证，不能由词典条目自动生效。

## 11. 用户方法、数量归属和研究结果的新所有者

| 用户可见概念 | 唯一所有者/词典ID | 解释边界 |
|---|---|---|
| 草稿/试用/使用中/退役 | `mode_cards.ModeCardService`；`state.method_draft/trial/active/retired` | 方法使用/实验状态，不是行情阶段、优势成立或执行开关 |
| 自建模式确切版本 | `ModeCardService.get_definition_snapshot`；动态`mode.user.*` + `mode-card-vN` | 未指定版本拒绝；退役仍保留旧定义；owner升级不强迫旧实验更换已冻结规则 |
| 开发/验证区间及预登记 | `ModeCardService.save_hypothesis` | 区间不重叠；主协议改动重置服务器登记时点，包含可选mode_ref的采用/改变/解除；参数尝试另有真实保存时间，不能共用旧登记身份 |
| 真实成交/模拟/观察/无结论报告 | `ModeCardService._append_items`；`result_type.actual_trades/simulation/observation/inconclusive` | 有来源的报告值仍非机器验证；观察不能填成交易胜率/已实现收益；无数据只保留备注与未知 |
| 主观模式、环境、角色及执行标签 | `analytics._decision_dimension`；`scope.subjective_labels` | 来自实际决策原文，unknown/mixed保留；标签不自动分配股数或收益 |
| 逐股模式归属 | `allocations.TradeAllocationService`；`scope.quantity_allocation` | 按fill_id + exact mode_ref + quantity，卖出还指向实际FIFO buy_lot_id；买入归属不足、多个成本批未拆等保持未知 |
| 完整轮与模式切片 | `analytics.JournalAnalyticsService.report`；`scope.closed_episode/mode_slice` | overall每真实清仓轮一次；mode分组可出现一轮的不同数量切片，分组n不能相加冒充独立交易次数 |
| 模式未分配残余 | `JournalAnalyticsService.report`；`scope.unallocated_mode` | 代码字符串mode.unallocated是统计占位，不登记为可选择的意图模式；真实现金结果保留，模式收益未知 |
| 分组获利比例与收益损失比 | `analytics._stats`；`metric.group_win_rate/group_profit_factor` | 显示n与episode_n、样本单位、已知/排除名单；无亏损分母为未知，不报无限优势 |
| 模式切片盈亏/成本回报 | `TradeAllocationService._calculate`与`analytics._stats`；`metric.mode_slice_pnl/mode_slice_return` | 复用实际FIFO含费成本按真实股数切分，与账户整体及未分配残余对账；不另算一份真实总收益 |
| 当前组合快照与既有stop风险合计 | `analytics.PortfolioRiskService`；`scope.current_portfolio_snapshot`、`metric.current_portfolio_value/configured_stop_risk` | 本次真实captured_at、原报价时点、已有资产/风险配置与情景；不是过去交易时的账户、组合VaR或止损保证 |

这些新增对象只在`trade_journal_*`范围保存，不修改生产持仓或策略注册表。模式/假设修订共享journal写租约及身份+revision唯一约束；数量归属、组合快照分别有自己的版本与内容身份。各owner的阈值或已有计算器仍是唯一实现，词典不复制参数生效逻辑。

数值报告必须有已归档来源、正分母和不晚于保存日的数据截止；胜数/分母与所填比例一致。真实交易类型还需实际成交来源；模拟及观察分别标识。结果在登记验证窗口内只表示日期范围相符，窗口外为探索/历史报告，均不自动通过收益验证。更正追加新结果与原result_id关系；旧失败阈值和报告不删除。

当前组合视图保留quote_at、原始报价质量及缺项；配置中的total_assets不是已核验券商净资产。没有完整逐日权益与资金流时，equity_curve/max_drawdown继续未知，不把当前组合快照拼成历史净值。用户提出的买卖情景是建议输入，始终与实际委托、成交及真实账户事实分开。

## 12. 原件导入、待办、事实匹配与过程复盘协议

2026-10-28追加的记录协议不改变前述交易阈值、资格或策略版本。新协议各有独立所有者与实现版本，均复用原ECS journal存储、原FIFO和现有生产成交所有者。

| 概念 | 唯一所有者 | 明确口径 |
|---|---|---|
| 原件识别与字段映射 | `import_files.inspect_file/parse_file`，`eastmoney-file-adapter-v1` | 以文件内容识别XLSX/CSV等支持范围，原件最多8MiB；列映射、人民币币种、日期、时间性质和现金符号须明确。非空表/行不能静默遗漏，忽略必须有理由；未解决行不产生可提交的部分payload。公式缓存、宏和外部链接不作事实。 |
| 成交时刻与交割发生时刻 | 原parser和`TradeJournalService._normalize` | 真实成交时间只由明确成交字段或已配对旁证给出；发生时刻另存。双表配对不产生两笔成交，同价量多解须指定原行对。成交编号保留前导零，不能先转数值或全局去零。 |
| 对账预览与确认 | `TradeJournalService.preview_import/import_batch` | parser只生成规范输入，实际重复/冲突及库存核对仍由原owner负责；预览不写库，最终提交携带原payload及preview_digest，提交锁内再核对。历史导入不重放到生产现金、持仓、订单或执行集合。 |
| 同源原行及跨源身份别名 | journal导入身份接合 | 原件内容SHA、确切工作表/行是强定位，不能用文件名或相同价量替代。跨源别名须保留原始双方编号、canonical事实ID/hash、来源定位和明确核对理由；只处置身份，不修改原现金事实或补造缺失费用。 |
| 缺项待办 | `tasks.JournalTaskService`，`trade-journal-tasks-v1` | 由真实缺项、资格原因及实际复盘事实投影，同一轮同根因归并。`open`待处理；`confirmed_unknown`仅表示用户确认当时未设/无法恢复；`ignored`表示有理由暂不处理；`resolved`只由当前所缺事实实际补齐而产生。后三者不是样本资格升级。 |
| 待办重开与并发 | 同上 | 处置必须携带打开时的revision与fact_fingerprint。相关原事实或缺项变化后旧确认/忽略失效，重新待核；无关字段修订不反复重开其他根因。历史理由与实际服务器记录时刻保留，不能用刷新后的版本号覆盖旧表内容。 |
| 到期预期核对与过程复盘 | `tasks`的`review/process_review`根因 | 到期核对必须有原记录的明确验证时点；无验证时点不虚设期限。已清仓但无当前已确认过程复盘的轮，另进入过程复盘队列。确认未知/忽略待办不等于实际完成过程复盘。 |
| 生产回写与归档同一事实 | `execution_matches.ExecutionMatchService`，`journal-execution-matches-v1` | 同证券/日期只形成候选。确认须明确账户、同一真实成交、确切归档fill及原生产execution，并核对数量、金额、费用与净收付；时间/分笔差异另确认。现支持多个完整归档fill对应一笔生产回写，不按未知部分股数猜撮合关系。 |
| 匹配状态 | 同上 | `unmatched`无关联；`confirmed`为已记录的身份确认；`stale`表示原生产内容已变，旧确认需重核；`unlinked`为明确追加解除。未解除的旧关联不能把相同fill再分给另一个execution。保存/解除均不再次改现金、库存或总盈亏。 |
| 匹配的金额基础 | 同上及既有execution owner | 优先原件实际amount；生产侧有净收付及费用时按该实际现金关系核对。原owner存储四位均价，其乘股数的截位误差不能冒充实际现金差；价格与现金不一致仍要阻断。缺费用/净收付保持未知，身份关联不授予金额对账完成资格。 |
| 过程复盘六维 | `reviews.JournalReviewService`，`trade-journal-reviews-v1` | 入场、持有、退出、加减仓、仓位、信息质量分别保存原文、理由及可恢复证据。每维`unknown/as_planned/deviation/not_applicable`只表示用户记录的判断，`machine_verified=false`；空维保持unknown且user_supplied=false，不能从最终盈亏填违规。 |
| 过程复盘状态 | 同上 | `draft`草稿；`confirmed`仅表示用户已实际保存此次复盘，结论仍可unknown；读取时`missing`无记录、`stale`为关联原事实/确切决策版本变化需重核。原版本不被改写，新的确认须针对当前事实digest。该轴独立于已清仓、四维资格和因果是否成立。 |

“未提供”与“当时未设”必须分开：现有补记没有出现某字段，只能记未明确；只有用户明确说明当时未设或无法恢复，才保存相应确认。系统可提示缺口，不替用户作此确认。
