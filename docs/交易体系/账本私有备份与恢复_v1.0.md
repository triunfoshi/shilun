# 账本私有备份与恢复

版本1.0，2026-10-29。此流程复用现有ECS Mongo配置、官方Mongo Database Tools和交易账本写入租约；它不切换应用数据源，不恢复到生产库，不更改生产持仓、风险配置、订单或成交回写。

## 范围与截止

`shilun.jobs.mongo_backup_job`创建配置中的整个业务数据库原生gzip归档。账号、密码不进入命令行或公开回执；官方工具通过临时0600配置文件读取连接，调用结束删除该临时文件。归档目录0700、原件/manifest/日志0600，不通过静态文件或分享地址发布。

账本写入使用已有`TradeJournalService.write_guard()`，归档期间续租。开始前捕获全部`trade_journal_*`持久集合及索引，结束后重新核对。仅排除临时`trade_journal_write_locks`，恢复时也不恢复过期租约。新出现的持久账本集合自动进入清单，不能只备份预先写死的成交表。

实际ECS为standalone。该逻辑归档不宣称其他行情集合在同一瞬间一致；写屏障与精确截止校验覆盖账本，其他集合保留归档窗口。这遵循[MongoDB对并发写入与mongodump的一致性说明](https://www.mongodb.com/docs/database-tools/mongodump/)。整个业务库归档仍保留研究、账户等依赖，不能用几份JSON统计替代恢复数据。

## 校验清单

`shilun.trade_journal.recovery`只读捕获和验证：

- 所有持久账本集合的完整BSON内容指纹、数量和索引；保留`_id`、Int64、Binary、空值与零的区别，复合索引键顺序不变。
- 通过原所有者恢复原件字节及SHA、快照内容/版本，不复制大段正文到manifest。
- 批次→来源/成交/财务事件、决策→库存轮/成交/确切计划、跨票关联→确切决策版本、复盘/待办/分配/成交匹配→原事实引用。
- 使用原FIFO和资格所有者重算账本及统计摘要；不另外实现收益算法。合法的事后补记、未知、草稿和stale复盘保持原样，不因恢复而提高资格。

manifest、原生归档SHA、恢复回执是不同证据：SHA相等证明文件未变，只有实际隔离恢复并重算通过才证明此次账本恢复链可用。

## 操作

准备新的私有父目录，使用现有配置执行：

```sh
./.venv312/bin/python -m shilun.jobs.mongo_backup_job backup \
  --directory runtime/private-backups/唯一新目录 \
  --receipt outputs/唯一备份回执.json

./.venv312/bin/python -m shilun.jobs.mongo_backup_job restore-verify \
  --directory runtime/private-backups/唯一新目录 \
  --database shilun_recovery_唯一新验证库 \
  --receipt outputs/唯一恢复回执.json
```

工具先核实本地归档空间及Mongo服务器恢复空间。目录、manifest、归档权限或SHA不符时，恢复未开始。源库和系统库不能作为恢复目标；目标必须匹配`shilun_recovery_`专用规则且不存在。原子创建验证标记防止两个恢复过程复用同一目标。

恢复使用明确的`--nsInclude/--nsFrom/--nsTo`，不使用`--drop`、`--oplogReplay`或用户角色恢复选项。命名空间重映射依据[官方mongorestore说明](https://www.mongodb.com/docs/database-tools/mongorestore/)。本流程不提供生产覆盖命令，应用配置始终指向原业务库。

数据通过本机27018隧道访问ECS时，可给上述命令同时添加`--ssh-target 用户@既有ECS主机 --ssh-key 既有管理私钥路径`，在同一ECS的127.0.0.1:27017上调用原生工具。这样先在ECS本机压缩归档，再通过SSH传输压缩文件；恢复也在ECS执行。该选项保留SSH主机校验，不自动安装工具或更改连接配置；Mongo凭据仅在加密stdin和私有临时配置中传递，命令参数没有密码。账本截止与写入屏障仍由同一原所有者核对。

失败会保留私有日志、失败回执和隔离库，不自动删除或把部分结果标为成功。重试用新的验证库；撤销/清理验证库须核对原任务标记及回执，不能以通配符删除数据库。归档的本机副本及ECS副本都应校验SHA后保留。
