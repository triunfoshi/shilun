# 实时打板情绪数据源比较

## 结论

两套接口回答的问题不同，不能用一个“谁更快”覆盖全部指标：

| 场景 | 当前来源 | 判断 |
| --- | --- | --- |
| 个股/指数现价与时间戳 | 石论现有 Tushare 实时适配器（底层为新浪行情） | 原始报价更适合做秒级价格新鲜度校验；本地适配器保留 `quote_at`。 |
| 涨停、炸板、跌停、连板与晋级率 | Vibe-Astock 同口径的东方财富 `push2ex` 四池 | 指标覆盖更完整；盘中 15 秒 TTL，非连续交易时段回溯最近有效收盘池。Tushare 的 `rt_min` 是实时分钟数据，不直接提供四个打板池。 |

因此 P2 的“今日实时打板情绪”以东方财富四池为主源，明确显示抓取时刻、缓存周期和快照模式：连续交易时段显示盘中读数，盘前、午休、收盘后及非交易日显示最近有效交易日收盘状态；若最近收盘池也不可取得，才显示缺失。Tushare/Sina 继续服务价格与分时数据，不把价格接口硬凑成打板情绪。当前没有在同一 ECS、同一时刻做两个网络链路的延迟基准，所以结论是“按接口能力与刷新机制选择”，不是宣称某一网络永远更快。

## 口径

- 涨停数：`getTopicZTPool` 返回的有效池行数。
- 炸板数：`getTopicZBPool` 返回的炸板未回封池行数；不能用涨停池单行的 `zbc` 代替全市场炸板家数。
- 跌停数：`getTopicDTPool` 返回的有效池行数；空列表是有效的 0，取数失败则保持缺失。
- 封板率：涨停 /（涨停 + 炸板）。
- 炸板率：炸板 /（涨停 + 炸板）。
- 晋级率：上一交易日涨停池中，今日再次封住的比例；上一交易日样本缺失时显示“待取”，不显示 0%。
- 快照模式：`live` 为连续交易时段盘中读数，`settled` 为最近有效交易日收盘快照；`snapshot_date` 与请求当天分开显示，避免把历史收盘状态误写成今日实时。
