# 紫阳东路—指数环境研究方案 v1.0

> 研究对象：国泰海通证券股份有限公司武汉紫阳东路证券营业部在公开交易信息中的出现记录，以及这些记录对应的指数环境。  
> 研究阶段：先完成可审计的数据集、图表和描述性分析，不预设规律，不直接形成交易信号。  
> 口径边界：公开龙虎榜是营业部级汇总，不是客户逐笔交割单，也不是该营业部的全部交易。

## 1. 本期目标

本期只回答四件事：

1. 在现有数据接口中，能否完整、稳定地获取紫阳东路公开买榜记录；
2. 紫阳东路公开买入发生时，当日及此前若干交易日的指数处于什么状态；
3. 现有 PART1 大盘指标在这些日期上分别给出了哪些事实、分数和权限；
4. 能否形成一套可复算、可画图、可继续扩充的 Excel 研究底稿。

本期不回答“紫阳东路为什么买”“该席位是否具有预测力”“哪个指数形态必涨”，也不直接输出胜率结论。

### 2.1 数据源决策

采用“统一源优先、交易所源兜底、第三方只核对”的三级方案：

1. **首选 Tushare `top_inst`**：恢复可用凭证后，按交易日遍历全历史，筛选目标营业部全部名称别名；用 `top_list` 核对当日上榜证券覆盖。
2. **若 Tushare 权限未恢复**：上交所主板/科创板与深交所公开信息分别采集，再合并为统一表。上交所主板最早统一从 2017-01-01 开始；其他市场以各页面实际可追溯日期为准，并在报告中单列覆盖边界。
3. **第三方聚合数据**：只用于发现漏项、核对名称与金额。若与交易所源冲突，以交易所公开信息为准，并把差异写入质量检查表。

因此，在私有 Tushare 网关续费前，项目可以立即完成沪市研究，但不能把沪市样本称为“紫阳东路全部买入日期”。

## 3. “全部买入日期”的严格定义

### 3.1 营业部名称别名

首版至少匹配：

- `国泰海通证券股份有限公司武汉紫阳东路证券营业部`
- `国泰君安证券股份有限公司武汉紫阳东路证券营业部`

采集阶段先保留源端原名 `branch_name_raw`，再映射为统一名称 `branch_name_canonical`。只包含“武汉紫阳东路”但券商主体不属于已确认别名的记录，进入人工复核，不自动并入正式样本。

### 3.2 三种日期不能混用

| 字段 | 含义 | 是否可称为确切买入日 |
|---|---|---|
| `disclosure_date` | 公开信息披露/榜单日期 | 否，只代表信息何时公开 |
| `period_start` / `period_end` | 公开金额对应的统计区间 | 只有起止同日时可以 |
| `exact_buy_date` | 单日榜单中可确认为该营业部进入买入前五的交易日 | 是 |

若上榜原因是三日累计、十日累计等，公开金额是一个区间累计值，无法知道具体哪一天买入。此类记录标为 `WINDOW_BUY`，只研究窗口结束日及窗口内指数路径；不得把窗口结束日伪装成全部成交发生日。

### 3.3 买入事件定义

正式事件主键建议为：

```text
event_id = source + ticker + period_start + period_end + branch_name_canonical + buy + sell + net_buy
```

入池条件：

1. 营业部名称命中已确认别名；
2. 该营业部出现在买入金额前五名单，或源端 `side=0`；
3. `buy_amount > 0`；
4. 记录能追溯到源 URL、查询参数、抓取时间和原始记录哈希；
5. 能识别为 `EXACT_BUY` 或 `WINDOW_BUY`，无法识别的进入隔离区。

### 3.4 去重与金额规则

龙虎榜最容易因“多上榜原因”“同时进入买榜和卖榜”“多个页面重复披露”被重复累加，必须按下列顺序处理：

1. 完全相同源记录去重；
2. 同一股票、统计区间、营业部、买卖金额相同，仅 `side` 不同，保留一份金额并记录 `appeared_on_both_sides=true`；
3. 同一金额因多个披露原因重复出现，只保留一份金额，原因合并成数组；
4. 不同统计窗口相互重叠时，不跨窗口求和；
5. 单日金额与多日累计金额分别排序，不能混成一个“大额买入榜”。

## 4. 研究样本与观察窗口

### 4.1 事件层级

建立三个互不混淆的样本层：

- **明细事件层**：一只股票、一个统计区间、一个营业部公开记录；
- **日期汇总层**：同一确切买入日内，对不同股票的去重买入金额求和；
- **窗口观察层**：多日累计榜单单独保留，不并入单日金额排名。

主要分析以 `EXACT_BUY` 为核心，`WINDOW_BUY` 作为补充案例。

### 4.2 指数观察区间

每个事件固定建立：

- 前视窗口：`T-20` 至 `T`，重点展示 `T-10` 至 `T`；
- 同期快照：`T` 日收盘后的指数形态与 PART1 指标；
- 后验窗口：`T+1`、`T+3`、`T+5`，只作描述性标签，不进入当日特征；
- 指标预热：每个指数至少读取 `T` 前 60 根日 K，推荐 120 根。

`WINDOW_BUY` 的锚点使用 `period_end`，同时画出整个 `period_start` 至 `period_end`，图上明确涂色标注公开金额对应的是一个区间。

### 4.3 指数映射

| 股票板块 | 主指数 | 辅助指数 |
|---|---|---|
| 沪市主板 | `000001.SH` 上证指数 | `000300.SH`、`000905.SH`、`000852.SH` |
| 深市主板 | `399001.SZ` 深证成指 | `000300.SH`、`000905.SH`、`000852.SH` |
| 创业板 | `399006.SZ` 创业板指 | `399001.SZ`、`000852.SH` |
| 科创板 | `000688.SH` 科创50 | `000001.SH`、`000852.SH` |
| 北交所 | 先记录市场标识，待项目接入稳定北证基准后再入正式比较 | 沪深宽基仅作旁证 |

日期汇总层另外固定观察上证指数、深证成指、创业板指、沪深300、中证500和中证1000，避免单一指数掩盖风格分化。

## 5. 指数三形态与现有大盘计算

### 5.1 研究形态只分三类

| 形态 | 硬定义 |
|---|---|
| `M_UP` 上升 | `close > MA20`、`MA20_5d_slope > 0`、`return_5d > 0` 同时成立 |
| `M_DOWN` 下跌 | `close < MA20`、`MA20_5d_slope < 0`、`return_5d < 0` 同时成立 |
| `M_RANGE` 震荡 | 不满足上升或下跌全部条件 |

三分类是研究标签，不替代现有 PART1 的 `attack/hold/defense/empty` 权限状态。两者同时保存，用于观察“简单趋势状态”和“完整大盘权限”之间的关系。

### 5.2 复用现有 PART1 指标

每个事件日按当时可见数据调用现有 `evaluate_market_permission`，保存原值，不重新设计评分：

- 趋势：指数 OHLC、MA5/10/20/50/120/250、均线斜率、20 日高低、自动支撑/压力；
- 量能：成交额、成交额 MA5/MA20、`amount_ratio_5/20`、上影比例；
- 广度：上涨/下跌家数、上涨占比、涨跌停家数及其 5 日均值；
- 主线代理：行业收益、行业上涨占比、行业成交额占比、权重护盘标识；
- 风险：放量破位、跌停扩散、爆量上影、多指数压力；
- 评分：`trend_score`、`volume_score`、`breadth_score`、`theme_score`、`risk_score`、`total_score`；
- 权限：`attack/hold/defense/empty`、硬触发项、行动权限。

`theme_score` 当前仍是行业聚合代理，报告必须标注 `proxy_only`，不能写成已经确认的市场主线。

### 5.3 追加的描述性指标

为便于画事件图，新增但不打分：

- 指数 `return_1d/3d/5d/10d/20d`；
- `T-10` 到 `T` 的累计收益、最大回撤、最大反弹；
- 当日振幅、收盘位置、开盘缺口；
- 主指数相对沪深300、中证500、中证1000的强弱；
- 最近 5 日三形态路径，例如 `UP-UP-RANGE-RANGE-UP`；
- 紫阳东路买入金额、净买入额、买入占股票榜单统计期总成交额的比例。

## 6. 大额买入重点观察规则

大额日期先作为“重点画图队列”，不作为模式条件。

### 6.1 单日精确事件

同一日期汇总后，满足以下任意两项标为 `HIGH_FOCUS`：

1. 日期总买入额处于全部确切买入日的前 20%；
2. 日期总买入额不低于 1 亿元；
3. 至少一只股票的营业部买入额占该股票对应统计期成交额不低于 2%。

阈值均放在 Excel 参数页，可在看到分布后调整，但每次调整必须增加规则版本，不能回写旧结果。

### 6.2 多日累计事件

按累计金额分位数单独排序，标记为 `WINDOW_HIGH_FOCUS`。它不与单日金额比较，也不参与“某一日出手总额”计算。

## 7. 数据加工流程

```text
数据源验收
  → 按交易日/交易所采集原始龙虎榜
  → 营业部别名匹配
  → 单日/多日窗口识别
  → 双边与多原因去重
  → 形成明细事件和日期汇总
  → 补齐股票及指数日线、全市场横截面
  → 计算三类指数形态与 PART1 全量指标
  → 建立 T-20…T+5 事件窗口
  → 质量检查
  → 作图、Excel、描述性报告
```

### 7.1 推荐落地步骤

**阶段 A：数据源打通**

1. 恢复 Tushare/私有网关 `top_inst` 权限；
2. 用 2026-07-20 已知沪市案例验收：应能命中紫阳东路，并与上交所公开金额逐项核对；
3. 若未通过，切换交易所采集方案，不等待供应商。

**阶段 B：全历史事件池**

1. 使用交易日历遍历有效日期；
2. 保存所有原始返回，不先筛掉非目标营业部；
3. 应用名称别名、日期类型和去重规则；
4. 输出事件覆盖统计、来源覆盖统计和异常清单。

**阶段 C：指数与大盘快照**

1. 按事件所需日期回填指数 120 日预热窗口；
2. 回填事件日全市场日线，以复算广度和 PART1；
3. 对每个事件写入三形态、PART1 分数、指标和可用时间；
4. 数据不足的事件保留，但 `analysis_eligible=false`，不以 0 代替缺失。

**阶段 D：图表与报告**

1. 先完成覆盖率、金额分布、三形态分布和重点日期图；
2. 再做事件前路径、基准日分布对比和大额子样本观察；
3. 只写事实和异常，不要求本期给出规律。

## 8. 图表清单

1. **全历史时间轴气泡图**：横轴日期，纵轴买入额，颜色为 `M_UP/M_RANGE/M_DOWN`，气泡大小为参与度；
2. **三形态分布对比**：紫阳东路确切买入日占比 vs 全部交易日基准占比，并计算 lift；
3. **重点日期指数事件图**：主指数 `T-20…T+5` K 线/收盘线、MA5/10/20、成交额、PART1 权限背景色；
4. **事件前路径图**：所有事件以 `T=0` 对齐，画 `T-10…T` 累计收益的中位数、四分位数和个体路径；
5. **金额与大盘指标散点图**：买入额/参与度分别对 `return_5d`、`amount_ratio_5`、上涨占比、风险分；
6. **日期热力图**：每个重点日期展示三形态、五维分数、广度和量能；
7. **数据质量图**：按来源、年份、市场展示缺失率、精确日/窗口日占比和去重数量。

首版重点日期图建议全部输出；若样本过多，则对 `HIGH_FOCUS` 全量输出，其余每个年份和每种指数形态分层抽样。

## 9. 数据分析文档结构

最终报告建议保存为 `outputs/reports/ziyang_index_environment_analysis_v1.md`，结构固定为：

1. 研究问题与不能回答的问题；
2. 数据源、覆盖期、营业部别名与披露边界；
3. 原始记录、去重记录、确切买入日和多日窗口数量；
4. 买入金额与参与度分布；
5. 三类指数形态下的事件分布与交易日基准分布；
6. 大额买入日期逐案图表；
7. 现有 PART1 指标在事件日的描述性结果；
8. 数据异常、缺失、窗口累计和可能偏差；
9. 暂不下结论的观察事项；
10. 下一轮拟验证假设。

报告中禁止使用“证明”“必然”“胜率”一类表述，除非后续完成基准对照、样本外验证和统计显著性检验。

## 11. 防时间穿越规则

1. 龙虎榜通常收盘后披露，最早从下一交易日才能成为可用信息；
2. 当日指数形态可以用于“同日环境描述”，不能反推为当天盘中可用信号；
3. `T+1/T+3/T+5` 只写到结果列，绝不进入特征列；
4. 每条事件保存 `feature_cutoff_at`、`disclosed_at`、`available_at`、`entry_eligible_at`；
5. 自动检查 `feature_cutoff_at <= disclosed_at <= available_at <= entry_eligible_at`；
6. 多日累计榜单不能假设买入发生在窗口结束日；
7. 历史计算使用当时上市状态、ST 状态、停复牌状态和当时可知的行业/成分；
8. 指数三形态的收盘后版本与盘前冻结版本分开保存，不覆盖历史快照；
9. 研究规则、数据、代码、别名表、去重规则均保存版本号。

## 12. 质量门禁与验收标准

### 12.1 数据门禁

- 原始记录 100% 带来源、抓取时间和原始哈希；
- 正式事件 100% 命中已确认营业部别名；
- `EXACT_BUY` 与 `WINDOW_BUY` 100% 分开；
- 双边/多原因重复金额不得重复累加；
- 每个正式事件至少有主指数 `T-20…T`，计算三形态时至少有 60 根预热日 K；
- 无法复算 PART1 的事件必须有明确缺失原因。

### 12.2 勾稽门禁

- 原始买入额经去重后等于事件表买入额；
- 日期汇总表只汇总 `EXACT_BUY`；
- 重点日期阈值引用参数页，不在公式中写死；
- 同一事件的结果列日期严格晚于特征截止时间；
